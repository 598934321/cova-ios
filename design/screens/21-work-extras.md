## 1. 屏与上下文

- **层级**：`modal` 半屏 sheet（present，z 序 `elevation.zOrder` 的 overlay 层，MiniPlayer 之上、
  Dialog 之下）。**同一容器两种宿主**：
  | 宿主 | 呼出位置 | 走的路径 | 计费 |
  |---|---|---|---|
  | **作品路径** | 20 作品行 ⋯ 的「补充制作」（本屏 §1 表与 §2 的「作品路径形态」）| `POST/GET works/:id/extras` | **不消耗 co**（§7） |
  | **会话路径** | 09 候选卡组终态后的「补充制作」区（09 §3.I 的完成位）| `GET/POST /api/studio/extras?sessionId=` | 按 key **消耗 co**（§7 价目表，`MEDIA_EXTRA_PRICES`） |
- **入口**：① 20 行 ⋯ →「补充制作」；② 09 交付区的补充制作钮；③ 深链 `work-extras`（带
  `job=` / `session=` 参数二选一）。**09 的那颗钮需 09 的持有者回写**（本任务不改 09，
  已在 `inventory.md` 行 09 登记交叉引用）。
- **两路径共用一个规格文件的原因**：契约 §4.4 明写作品级 extras 是
  「**同会话 extras 管线，幂等复用**」——同一套 key、同一套产物形态，只有**计费面**与
  **请求端点**不同。分成两屏会让「同一个交付物在两个地方数字不同」这件事失去唯一对照处。
- **两条腿的三处不同形（§4.7 实测，规格必须分开处理）**：
  | 差异 | 作品路径 | 会话路径 |
  |---|---|---|
  | 计费 | **不扣费**（§4.7 明写「作品级这一支服务端不扣费」）| 按 `MEDIA_EXTRA_PRICES` 扣 |
  | `deliveryRevision` | **不回** ⇒ 无版本对账腿（§3 的静默重取规则在作品路径退化为「重开即重取」）| 回（它是工作流计数器）|
  | 请求 id | **只认伪 id** `{jobId}:{candidateId}`，裸 jobId ⇒ **404** | `?sessionId=` |
- **与 20 的 `timing` 的区别（不许混）**：20 的「歌词」是 `GET works/:id/timing` 的**只读查看**
  （回 `{ok,lrc}`，不是交付物、不产生文件）；本屏的 `lyrics_timing` 是**产物 key**
  （会话路径 10 co，落盘一个文件）。两者在 UI 上不得共用钮、不得共用文案。
- **与 12d 的关系**：本屏的产物**不进** `12d-downloads.md` 的「已下载」清单（那是库曲付费
  下载清单，其门 1 未放行；手册 §7 #36 已把作品直存的落点与 12d 分开登记）。
- **返回**：下滑手势 / 点遮罩 / ✕ 关闭，回到来处屏且不改变其滚动位置。
  **登录门槛**：需登录（extras 三端点均需 Bearer；未登录 → 17-S6）。
- **D12 合规（本屏的立屏前提）**：
  1. 本屏**没有**任何购买/充值入口、没有余额充值话术；余额只在会话路径作为**扣费事实**出现一次
     （`§3.D`，取 `entitlements.creditsBalance`，与 09 §3.G 同一口径）；
  2. **作品路径不得暗示存在价目**：该路径**不渲染**每条 key 的数字、不渲染合计行、
     不渲染余额行，只给一句中性事实（`§8` 串「这里不消耗 co」）；
  3. 「保存」类动作的措辞沿用 19 已定稿的 `保存到本机` / `已在本机`，**不写**
     「下载（需要 co）」「解锁文件」这类把交付物和扣费绑在一起的话；
  4. §8 的每一个上屏字面量都按 `Scripts/d12-copy-check.sh` 的禁词表逐串核过
     （该脚本只扫 Swift 字面量与 plist、剥注释；本文件的**规则说明**里出现禁词是登记行为，
     上屏串里一个都没有）。

## 3. 区块规格

- **A/B 容器与顶部条**：`color.elevated` + 顶部 `radius.hero`；拖拽指示条 `color.line`
  （TG-16 几何）；✕ ≥44pt；标题「补充制作」`type.headline`（作品路径）/「补充制作 · 这次会话」
  （会话路径）——两条措辞都**不带**任何计费字样。
- **C 已完成交付物组**：分组标题 `type.caption` / `color.muted`（03/19 同档）。
  每条一行（最小高 52，TG-19）：左 符号按 key 类型（音频 `waveform` / 压缩包 `archivebox` /
  视频 `film` / 文本 `text.quote`，`color.secondary`，20pt 档 TG-18）+ `label`（`type.headline`）+
  副行（`type.caption` / `color.muted`）+ 右侧「保存到本机」文字钮（`arrow.down.circle` +
  `type.callout` / `color.accentText`，≥44pt）；已落本机 ⇒ `checkmark.circle` / `color.success`
  + 「已在本机」，再点 = 删除本机文件（二次确认 Dialog，17-S7，串同 19）。
  - **副行默认不渲染**：`files` 条目的字段名未文档化（契约只到 `{ok,files,deliveryRevision}`
    一层）⇒ 体积、时长、分辨率、容器格式（zip / lrc / mp4 之类）**一个都不猜**。
    上图的「48.2 MB」是**形态占位**（17 §9：示例数据不参与验收），只在「待答（1）」得到
    答复后按真字段恢复；标签里的「WAV」不在此列 —— 它就是 key 名 `wav`，不是推断出的容器。
    - 唯一恒真的信息是 key 的中文名（§8 文案清单）与**状态**（已完成 / 制作中）。
  - `files` 为空数组 ⇒ C 组连同标题整组不渲染（**不**显示「还没有交付物」空态，
    D 组本身就在教用户怎么做）。
- **D 可选 key 组 + E key 行**：
  - 行：勾选圈（22pt 档 TG-18；未选 `color.line` 描边 / 已选 `color.accent` 填充 + 白勾，
    与 12a §3 多选态同规格）+ 标签 `type.headline` / `color.fg` + 副标 `type.caption` /
    `color.muted`（一句「这是什么」，串见 §8）+（会话路径）右侧 `预计消耗 %d co`
    （`type.subhead` / `color.accentText`，数字 `type.mono`）。
  - **key 的展示顺序恒为**：`wav` → `stems` → `vocal_stems` → `accompaniment` →
    `lyrics_timing` → `lyrics_video`（按制作工序排，与响应数组顺序无关；服务端数组顺序未文档化）。
  - **不可用的 key 一律整行不渲染**（不是置灰、不是「当前不支持」的行内说明）——手册 §3.6 disabled
    规则 + 12d 门 1 的先例。纯音乐作品 ⇒ `vocal_stems` / `accompaniment` / `lyrics_timing` /
    `lyrics_video` **四项不渲染** —— 服务端在 `instrumental == true` 时就把
    `lyrics_video`/`vocal_stems`/`accompaniment`/`lyrics_timing` 滤掉了（契约 §4.7），
    客户端选项集**必须跟着滤**。早先版本在此处是**推断**，现已由实测卡坐实。
  - 已在途或已完成的 key ⇒ 行**从 D 组消失、出现在 C/F 组**（同一 key 不同时出现在两处，
    避免「再点一次会不会再做一遍」的疑问；幂等复用由服务端保证，见 §7）。
- **D2 合计行（仅会话路径）**：`type.subhead` / `color.secondary` +
  数字 `type.mono`；余额位 `type.caption` / `color.muted`。勾选数 = 0 ⇒ 整行不渲染
  （不写「预计消耗 0 co」，0 不是事实而是「还没选」）。`entitlements.creditsBalance` 取不到 ⇒
  **只显示合计、不显示余额位**（09 §8 同规则：**不得**显 0）。
- **F 制作队列（在途组）**：仅当某 key 处于「已提交未完成」时出现。行 = 符号 + 标签 +
  状态文字「制作中」（`type.caption` / `color.warning`）+ **不确定指示**（菊花，封面位/钮位专用
  规则 17-S8）。**pending 没有 url ⇒ 整行不渲染「保存到本机」**（09 §5「无 URL 就整钮不渲染」
  同判据）。无百分比、无剩余时间（`DEVELOPMENT.md` 无进度字段 ⇒ 不印百分比，19 §3.D 同规则）。
  队列空 ⇒ 整组不渲染。
- **G 主钮**：胶囊高 50、`gradient.brandButton`、白字 `type.headline`，文案「开始补充制作」。
  - 勾选数 = 0 ⇒ disabled 形态（`color.muted` 底/字）且**不显示任何解释文案**（同 19 §3.C：
    空选择不需要教训用户）；
  - 在途 ⇒ 菊花替换文字、**不可二次点击**（一次点击 = 一个幂等键，§7）；
  - 会话路径成功后 ⇒ 该行迁入 F 组，主钮回落可点，D2 合计行按剩余勾选重算；
  - 全部 key 都不可用（纯音乐且 `wav`/`stems` 也已做完）⇒ D 组与主钮**一并消失**，
    只剩 C 组（不出现「没有可做的了」这种空壳说明）。
- **H 事实行（仅作品路径）**：`type.caption` / `color.muted`，「这里不消耗 co」，
  位于主钮下方 `spacing.sm`。**该串的成立条件与局限见 §7 与「待裁决 1」**。

## 4. 状态变体

> 通用形态引用 `17-state-gallery.md`；本节只列本屏实例。

- **加载（首载）**：C/F 不骨架（它们可能整组不存在，12c §4 / 17-S1「不骨架可能不存在的可选区」）；
  D 组 4–6 行勾选圈骨架 + 两条文本条（`color.surface` 呼吸）；B 与主钮轮廓呼吸（TG-24）。
- **成功（提交后）**：乐观迁入 F 组 + 一次性 Toast「已开始补充制作」（会话路径）/
  「已开始制作」（作品路径）。**不**在 Toast 里报数字（数字已在 D2 说过，重复即噪声）。
- **错误**（全部**就地**，sheet 不崩）：
  | 触发 | 表现 |
  |---|---|
  | 首载 `GET`（extras 快照）失败 | **③ sheet 内整块替换**（07 §4 先例）：error 符号 + 「补充制作没取到」+ 主钮「重试」+ 次钮「关闭」 |
  | 提交失败 400（非法 key / 缺参数。注：§4.7 未逐项记录 extras 的错误档 ⇒ 按服务端原文处理，见「待答（9）」） | ② 行内：主钮下方一行服务端 `error` 原文（`type.subhead` / `color.error`），勾选保留 |
  | 提交失败 402 `credits_insufficient`（**仅会话路径**；§4.7 未记录 extras 的 402 载荷是否带 `required` ⇒ 缺值走「余额不足」那一句） | 「余额不足，本次需要 %d co」（19 §4 同串；`required` 缺失 ⇒ 「余额不足」）；**不**出现任何补余额引导 |
  | 409（幂等冲突 / 该 key 已在途） | 行内「这个已经在做了」+ 该 key 行迁入 F 组（以后端事实为准，不重复提交） |
  | 429 | 服务端 `error` 原文 + 不做倒计时（本仓 `HTTPResponse` 无 header 面，19 §4 同判据；extras 的限流值未文档化 ⇒ 见「待答（5）」） |
  | 502/503（上游失败） | 行内原文 + 主钮回落可点（**不**自动重发写操作，硬边界 5 的 UI 面） |
  | 401/403 | 关闭 sheet + 17-S6（会话层统一处理，各屏不各自弹登录框，17 §5 禁令） |
  | 取件失败（artifacts 端点） | 该行的「保存到本机」回落 + 行内「这个文件没取到，重试」 |
  | 空间不足导致写失败 | 行内「空间不够了，清一清再试」（12d 同串） |
- **离线**：C 组已落本机的产物仍可「已在本机」态浏览与播放（`file://`）；
  D 组、F 组、主钮**整块不渲染**（无网络则无可提交），顶部 17-S4 离线条（sheet 内为细条形态）
  「离线：补充制作需要联网」。
- **未登录 / 游客**：不可达（§1）。
- **Reduce Motion**：命中 `17-state-gallery.md` §S5 —— sheet 弹出直接呈现、勾选态一帧换色、
  行迁入 F 组的位移动画退化为一帧、Toast 一帧显消（仍 3s 消失）、菊花**保留**（指示性动效）。
  本屏**没有**进度条，因此无「进度动画」退化项。

## 6. 可访问性

- **朗读顺序**（sheet 为模态容器，底层内容不可被朗读）：「补充制作，标题」→ ✕ →
  C 组「已经做好的，N 项」→ 每条「母带 WAV，<副标>，保存到本机 按钮」/「…，已在本机，
  删除本机文件 按钮」→ D 组「可以再做的，N 项，多选」→ 每行「人声分轨，<副标>，
  预计消耗 50 co，复选框，未勾选」（作品路径**无**价目片段）→（会话路径）
  「本次合计预计消耗 40 co，余额 128」→（F 组）「制作队列，1 项」→「人声分轨，制作中」→
  主钮「开始补充制作，按钮」→（作品路径）「这里不消耗 co」（静态文本，随组朗读）。
- 勾选态必须由**语义值**表达（复选框 + 已勾选/未勾选），不得只靠颜色（15 §6 同规则）。
- 价目数字与「不消耗 co」都是**事实陈述**，不得放进错误色或告警衬底（D12 的精神：
  不把扣费渲染成风险提示，也不把不扣费渲染成奖励）。
- **Dynamic Type**：AX 档下 key 行的价目/副标换到标签下方第二行；D2 合计与余额两行堆叠；
  主钮保持单行满宽；C 行「保存到本机」文字钮与符号不换行但可全宽。
- **触控目标 ≥44pt**：✕ / 每个勾选行（整行为一目标）/ 每枚「保存到本机」/
  「已在本机」/ 主钮 / sheet 内重试与关闭 / 二次确认 Dialog 两钮。

## 7. 数据契约

| 用途 | 端点 | 请求 / 响应（**逐字取契约**） |
|---|---|---|
