# 25 · 搜索（页签根屏：落地页 + 结果态）

> G2 逐屏规格。基准 393×852pt。**2026-10-02 新增**（Apple Music 参照改版轮）：
> 原 03 §3 的 `.searchable` 从曲库迁出，独立为 `Tab(role: .search)` 页签根屏——
> 对齐 Apple Music iOS 26「搜索页签 = 浏览入口 + 检索」的分工。
> 数据源：`GET /api/tracks?search=`（结果）、`GET /api/library/taxonomy`（分类卡）、
> 搜索历史 = 本地账（沿用原 03 §3 规则：最多 10 条、可清空、D9 owner 绑定）。
> 值一律 token 路径引用；缺口登记见文末「Token 缺口」。

## 1. 屏与上下文

- **层级**：「搜索」页签的**根屏**（04 §2 `Tab(role: .search)`——栏位由系统钉在标签栏
  右端分隔位，激活后导航条呈现系统搜索域）。
- **入口**：① 标签栏搜索页签；② 各屏右上角「搜索」类按钮（若有）同样落到本页签
  （切换页签而非 push——页签语义先于栈内导航）。
- **互链**：分类卡 / 历史 chip / 结果行 → 本栈内 push `library(preset)`（04 §3：
  **不切到曲库页签**，当前栈 push 曲库列表复用件）；结果行 → 07 曲目详情 sheet（外壳级）。
- **返回**：根屏无返回钮；退出输入态 = 系统 `.searchable` 取消语义，回落地页。

## 3. 区块规格

### A 导航条 / B 搜索栏

- `.searchable` 修饰在本页签 `NavigationStack` 根视图，`placement` 沿用
  `.navigationBarDrawer(displayMode: .automatic)`；`prompt` =「搜索曲名 / 艺人 / 标签」
  （与原 03 §3 同一文案，口径不变）。
- 输入即搜：300ms 防抖 → `GET /api/tracks?search=`；`sort` 不带 `relevance`
  （§7 边界：无 search 的 relevance 已知 500，本屏搜索串恒非空才发）。
- **输入态布局**：搜索栏下方 = 结果列表（§3.E）+ 级联筛选条（复用 03 §2 筛选件，
  筛选叠加进同一请求）；建议区（输入前）= C 历史。
- 取消（系统手势）→ 清空 query、回落地页；历史不自动记录取消前的词
  （只有**执行过搜索**的词才入历史，沿用原口径）。

### C 搜索历史

- 本地账：最多 10 条、新词置顶、可单删/清空（`clear` 按钮在行尾，`color.muted`）；
  D9 owner 绑定（换账号不串历史）；点 chip = 填入搜索框并立即执行。
- 空历史 → 整区不渲染（不留标题）。

### D 分类浏览（本屏差异化区块）

- 三组网格：**按场景浏览**（`taxonomy.scene` 前 8）/ **按情绪浏览**（`taxonomy.mood` 前 8）/
  **按风格浏览**（`taxonomy.genre` 一级，前 8）——每维度取词表 `sortOrder` 前 8 项；
  某维度不足 4 项 → 该维度整组不渲染（不出现稀稀拉拉的半行）。
- 卡片：宽 = (屏宽 − 2×`pageGutter` − `spacing.md`)/2，高 72，圆角 `radius.card`；
  `color.surface` 底 + 左缘 3pt 标识竖条（场景 `color.tagScene` / 情绪 `color.tagMood` /
  风格 `color.accentSoft`→`color.accentText` 字标）+ 词条名 `type.headline`/`color.fg` 居中；
  **不放封面图**（taxonomy 无图数据；色条标识是唯一视觉手段，像 Apple Music 分类卡去图化）。
- 点卡 → 本栈 push `library(preset)`：预设该维度值，列表标题 = 词条名
  （03 §7 `LibraryPreset` 的 `title` 覆盖规则同「AI 音乐人」入口）。
- 组标题：`type.headline`/`color.fg`，与上组间距 `spacing.xl`。

### E 结果列表

- TrackRow 同 03 §4 全部规格（行高/快捷操作/标签胶囊/长按预览）；分页同 03 §5
  （滚到底自动加载 + 「已加载全部」）。
- 筛选条在输入态吸顶于搜索栏下（复用 03 §2 件，已选 chips 行同规）。
- 无结果：17-S2 变体——「没有找到『{query}』相关的歌」+「换个词，或按分类浏览」+
  次级 CTA「清除搜索回浏览页」。

## 4. 状态变体

- **加载（结果）**：8 行骨架（17-S1）；分类区骨架 = 6 张卡块呼吸。
- **错误**：结果首载失败 → 列表区错误条 + 「重试」（不整屏——分类浏览与历史仍可点）；
  分类区失败 → 该区静默隐藏（浏览入口是增强件，不是本体）。
- **未登录**：全功能可用（搜索是公开检索）；结果行的 ♡/下载动作仍按 03 §6 弹登录引导。
- **离线**：结果不可达 → 错误条「离线，搜索需要联网」；分类卡仍可点（进 03 复用件后
  由该屏自己的离线态承接）；历史正常。
- **Reduce Motion**：历史/chip 出现、卡片入场全部一帧呈现；无搜索态过渡动画。

## 5. 深浅双主题差异

- 全走 `color.*` 双 mode；分类卡底 `color.surface`（Dark 下 `color.elevated`，与 05 §5
  封面占位同规则——避免深底上「更深的灰」）。
- 标识竖条色（tagScene/tagMood/accentSoft）双 mode 已备（2026-10-02 起 `CovaColor`
  补齐 tagScene/tagMood 导出）。风格组的 `accentSoft` 竖条是**装饰标识**不是选中态
  （分类卡没有选中概念），v2.65.0 去橙化不波及此处（design/README「与 web 的统一
  设计语言」：accentSoft 可留作 tag 底/装饰）。

## 6. 可访问性

- **朗读顺序**：「搜索，标题」→ 搜索栏 →「最近搜索，N 项」（含「清空」钮）→
  「按场景浏览」组 → 每卡「{词条}，按场景筛选，按钮」→ 依次情绪/风格组；
  输入态下 = 搜索栏 →「筛选」→「结果，N 项」→ 行元素（03 §6 朗读规格不变）。
- **Dynamic Type**：AX 档分类卡降为单列（卡宽 = 屏宽 − 2×`pageGutter`，高 72 不变）；
  词条名 1 行截断。
- **触控目标**：每卡 ≥44pt（高 72 天然满足）；历史 chip、清空钮 ≥44。
- 系统 `role:.search` 页签的「搜索，标签页」朗读由系统承担（04 §8）。

## 7. 数据契约

| 用途 | 端点 | 说明 |
|---|---|---|
| 搜索结果 | `GET /api/tracks?search=&page=` | 沿用 03 契约；`sort` 不传（服务端默认），禁 `relevance`（已知 500） |
| 分类卡 | `GET /api/library/taxonomy` | `scene/mood/genre` 三维；本地缓存、冷启动刷新（03 §7 同口径） |
| 搜索历史 | 本地 | D9 owner 绑定；15 屏「清除缓存」的本地数据清单含本账 |
| 进入曲库列表 | `library(preset)` 路由参数 | 不发新端点；预填值进 03 既有请求参数 |

- **不发明**：分类卡不请求任何「分类封面」字段（taxonomy 无图）；历史不上报服务端。

## 8. 边界与文案

- **历史溢出**：>10 条时最旧的被淘汰；重复词去重置顶。
- **文案清单**：`搜索` / `搜索曲名 / 艺人 / 标签` / `最近搜索` / `清空` /
  `按场景浏览` / `按情绪浏览` / `按风格浏览` / `没有找到『%@』相关的歌` /
  `换个词，或按分类浏览` / `清除搜索回浏览页` / `离线，搜索需要联网` / `已加载全部`。
- **零结果与空历史并存**：落地页只有分类区时合法；两区皆空（词表也未取到）→
  落地页只留搜索栏 + 17-S2 简版空态（「输入关键词找歌」）。

## 9. 验收判据

- [ ] 标签栏第五格为系统搜索位（分隔、右端、系统图标）；激活进入本屏
- [ ] 输入 → 300ms 防抖后发 `search=` 请求；取消回到落地页且历史不含未执行的词
- [ ] 历史上限 10 条、点词即搜、清空生效；换账号登录后历史不串（D9）
