## 4. 状态变体

- **加载（首访）**：组 1 两条文本骨架 + 圆形头像块；组 2 数值位显 `--`
  （余额是「值」不是「文字」，`--` 比骨架更少误解）；组 3 四行骨架。骨架 `color.surface` 呼吸（17-S1）
- **空态**：本屏无空态（账号信息恒有）。资产行右侧值为 0 时显「0」（真实零值 ≠ 无数据）
- **错误**：
  - `me` 首载失败但有缓存 → **行内**：组 2 数值位保留缓存值 + 右上一次性
    「未同步」（`color.muted`），**不**弹 Toast、**不**整屏（本屏其余入口全部本地可导航）
  - 无缓存且失败 → 整屏错误态（17-S3）「账号信息没取到」+「重试」
  - 资产计数拿不到 → 行右侧值整段不渲染（不显 `--`，避免与余额 `--` 混淆语义）
- **离线**：等同「有缓存的 `me`」路径（未同步 + 缓存值）；E 入口仍全部可导航，目标屏各自处理离线
- **未登录 / 游客**：本屏是页签根屏（§1），游客态根区 = 17-S6 引导形态（04 §6），
  不出现 B/C/D/E/F 各组。
- **登出竞态**：他端吊销/401 刷新失败 → 本屏当帧回落为「未登录」形态：组 1/2 隐藏、
  只留一行「登录状态已过期」+ 主钮「登录」→ 10；**不**弹额外 Dialog（15 主动登出才走 Dialog）
- **Reduce Motion**：present/push 动画退化为一帧；数值滚动（余额变化时的滚动动画）关闭，
  直接显新值；未同步提示的淡入淡出退化为一帧

## 8. 边界与文案

- **截断**：名字 1 行；邮箱中段截断；Cova 号不截断（超长则 2 行，仍不换行到 3 行）
- **零余额**：`creditsBalance = 0` → 显「0 co」，**不加**任何催促文案、**不加**「去充值」按钮、
  **不加**红色警示（0 不是错误态）。这是 D12 的关键落点：**余额为 0 时本屏与满值时完全同构**
- **负值/异常值**：契约 `creditsBalance` 为整数；若返回负数或异常大值 → 数值位显 `--` + 「未同步」
  （不显示可疑数字）
- **极值**：邮箱超长（>64 字符）→ 中段截断；名字为 emoji/中文混排 → 单行截断不折行
- **并发**：下拉刷新与 09 的流式对账互不阻塞（不同端点）；`me` 返回时若用户已 push 到 15，
  静默更新，不弹提示
- **文案清单**：`我的` / `余额` / `co` / `未同步` / `有效期至` / `我的资产` / `收藏` / `我的歌单` /
  `我的创作` / `已下载` / `商业` / `会员权益` / `企业服务` / `其他` / `设置` /
  `版本` / `登录状态已过期` / `登录` / `账号信息没取到` / `重试`
- **套餐四档中文**（全站唯一源，13 会员页与 04 引用本表）：`free` → 免费版 / `creator` → 创作版 /
  `pro` → 专业版 / `enterprise` → 企业版

## C2 每日签到（2026-09-27 加，§5 P3 第二条线）

- 位置：组 2 之下、组 3（我的资产）之上，**独立一行**（不并进组 2 —— 组 2 按 §验收第 1 条整组不可点）。
- 数据源：`GET /api/me/checkin` → `{checkedInToday, dailyAmount}`；领取 `POST /api/me/checkin`
  → `{ok, alreadyCheckedIn, granted, balance}`。**幂等在服务端那一侧**（route 注释：
  "重复点击/多 tab 不重复入账"），所以客户端不带幂等键 —— 硬边界 5 管的是扣费写操作，
  签到是发放，这句话不冒领别人的功劳。
- 三态：
  · 可签 = 「签到领 N co」（N 只从 `dailyAmount` 来）+ 礼品卡图标 + 右尖角，是一枚钮；
  · 已签 = 绿勾 + 「今天已签到」，**是一行说明不是钮**（摆一枚点了不会给任何东西的钮比不摆更坏）；
  · 读不懂 / 缺键 / 额度被配成 0 ⇒ **整枚不出现**（`.unknown`）。
- 在途：点下去换菊花并禁用第二次点击 —— 那是"手不抖"，不是协议保证，文案与注释都不许这么写。
- 失败只说「这次没签到，可以再来一次」：服务端对失败没有机器可读的码，
  编一句"额度已发完"就是替后端写文案。
- D12：这一格不出现"充值/购买/升级/限时"任何字样；它发放的是 co，不是钱，
  也不给任何付费入口。余额那一格仍按 §3.C 只读。
- 设备证据：`docs/acceptance/p3-20260927/11-mine-checkin-{light,dark}.png` +
  `25-checkin-{before,after}-tap.png`；屏外对账到 `+10 每日签到` 那一行流水。
- ⚠ 已知缺陷（§7 #53）：签完之后余额那一格在证据图里仍是旧值 ⇒ "签成功"与"余额跟上"
  是两格判据，本屏只过了前一半。
