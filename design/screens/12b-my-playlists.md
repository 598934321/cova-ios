# 12b · 我的歌单（收藏的官方歌单）

> G2 逐屏规格。基准 393×852pt。要点源：`inventory.md` 行 12（同构四屏之一）。
> **骨架基线见 `12a-favorites.md` §2–§6**（布局骨架 A–E、状态规范引用、a11y 通则）；
> 本文件只写差异。数据源：`GET /api/saved-playlists`（api-contracts §2）。

## 1. 屏与上下文

- **层级**：push 自 04/11；入导航栈。同 12a。
- **入口**：① 04 抽屉「我的资产 → 歌单」；② 11 我的 → 我的歌单行；③ 深链 `saved-playlists`。
- **互链**：卡 → 06 歌单详情；卡上 ⋯ → 「取消收藏」；空态 CTA → 05 歌单广场。
- **返回**：同 12a。从 06 返回时若该歌单已被取消收藏 → 行即时移除（本地态共享）。
- **登录门槛**：需登录；游客进入走 17-S6。
- **与 05 的关系**：05 是发现场（全量官方歌单），本屏是「我收藏的」子集，**不是**个人自建歌单——
  v1.0 无个人歌单创建端点（12a 待裁决 4），屏标题与空态文案必须避免「新建歌单」暗示。

## 3. 区块规格（只写差异）

### B 摘要行

- 口径：「N 个歌单 · 约 M 首」。`M` = 各歌单 `trackCount` 之和（**不做跨歌单去重**——
  去重需拉全部详情曲目，代价不可接受；文案用「约」承担误差）。
  若后端 `trackCount` 缺失（`PlaylistDto.trackCount` 可空）→ 该歌单不计入 `M`；
  全部缺失 → 摘要退化为「N 个歌单」

### C PlaylistRow（本屏主行）

- 容器：整行一个主点击目标；左右 `spacing.pageGutter`；上下内边距 `spacing.md`；
  最小高 104（TG-19 邻近档，行内 88 封面 + 边距）
- 封面：88×88（TG-31 同族尺寸档），圆角 `radius.control`（比 12a 的 TrackRow 封面 8 更大一档，
  缺口共用 TG-31）；裁剪按 `coverMedia.fit / focalX / focalY`；缺 → `color.surface` + 音符占位
- 文本栈（间距 `spacing.sm`）：
  - 标题 `playlist.titleCn ?? title`：`type.headline` / `color.fg`，2 行
  - 元信息 `trackCount` 首 + 「· 收藏于 <相对时间>」：`type.subhead` / `color.secondary`，1 行；
    数字 `type.mono`
- 右侧 ⋯ 图标按钮（≥44pt 热区 TG-03）→ 菜单：「取消收藏」（destructive，`color.error` 文字）
- 播放中指示：本屏**不显示**「正在播放」行态（歌单不是播放对象，队列归属在 06）
- 左滑动作（E 区）：同 12a §3.E，但语义 = 取消收藏（`bookmark.slash` 图标），**不弹**二次确认
  （可逆动作：去 05/06 可重新收藏）

### 多选态

- 同 12a §3；批量动作只有「取消收藏（n）」；勾选圈与行几何同 12a

## 4. 状态变体（只写差异）

- **加载**：4 行 PlaylistRow 骨架（88 方快 + 两条文本条）
- **空态**：插画位 + 「还没收藏歌单」(`type.headline`/`color.fg`) +
  「在歌单广场点书签，就会出现在这里」(`type.callout`/`color.secondary`) +
  主 CTA「去歌单广场」→ 05。（**不出现**「新建歌单」字样——v1.0 无该能力，见 §1）
- **错误**：首载失败整屏；刷新 Toast；取消收藏失败 → 行回落 + Toast「取消收藏没保存上，再试一次」；
  批量部分失败 → Toast「N 个没取消成功，已保留在列表」
- **离线**：有缓存 → 正常 + 离线条；取消收藏排队（与 12a 待裁决 3 同口径）；无缓存 → 整屏
  「离线：歌单收藏需要联网」
- **未登录**：同 12a；他端登出 → 本屏清空并回落 17-S6
- **Reduce Motion**：同 12a；封面入场无缩放

## 5. 深浅双主题差异

- 与 12a 同：全部走 `color.*` 双 mode（`canvas/surface/lineSubtle/fg/secondary/muted/elevated/error`）
- 封面在 Dark 下不加描边（占位块由 `color.surface` 与 `color.canvas` 的差值区分）
- 本屏无玻璃、无渐变

## 6. 可访问性

- **朗读顺序**：「我的歌单，标题」→ 编辑 →「5 个歌单，约 96 首」→「歌单列表，5 项」→
  每卡三元素：「<标题>，<N> 首，收藏于 3 天前，按钮」/「更多操作，按钮」/（滑开后）
  「取消收藏，破坏性操作，按钮」
- 封面 `accessibilityHidden`；`coverMedia.alt` 存在时并入卡标签尾部（与 05 同规则）
- **Dynamic Type**：AX 档下封面 88 → 保持（图像不随文本放大），标题允许 2 行、元信息允许 2 行，
  行高由内容撑开；B 摘要 2 行
- **触控目标 ≥44pt**：全部同 12a，另加 ⋯ 菜单项「取消收藏」

## 7. 数据契约

| 用途 | 端点 | 字段 |
|---|---|---|
| 列表 | `GET /api/saved-playlists` → `{playlists[]}` | `PlaylistDto` + `savedAt`（CovaCore 已按真实响应建模，见 `CollectionDTOs`）；本屏用 `id/title/titleCn/cover/coverUrl/coverMedia/trackCount/isSaved/savedAt` |
| 取消收藏 | `DELETE /api/saved-playlists`，body `{playlistId}` → `{saved, playlistId, action}` | 以 `saved` 回填（false = 已取消） |
| 收藏（新增） | `POST /api/saved-playlists` | 由 06 发起；本屏只消费结果 |
| 批量 | **无批量端点** → 逐条 DELETE（同 12a 待裁决 1） | — |

- **排序**：本屏**可以**按 `savedAt` 倒序（与 12a 不同——该响应带 `savedAt`）。
  规则：客户端按 `savedAt` 倒序稳定排；`savedAt` 缺失的条目排在末尾并保持后端相对顺序。
  **不显示**绝对时间戳以外的时间信息
- **分页**：响应无分页封套 → 全量 + 「已显示全部」；下拉刷新重取；缓存 ≤ 5min（TG-09）
- **NEEDS 关联**：
  - 本屏不依赖 NEEDS-9（列表端点**有** `isSaved`；缺的是详情端点，见 06 §7）
  - NEEDS-1/3 未解锁只影响能否登录，不影响本屏字段
- **可空规则**：`trackCount` 空 → 元信息退化为「收藏于 …」；`savedAt` 空 → 省略「收藏于 …」段；
  两者都空 → 元信息整行不渲染；`cover*` 全空 → 占位；`title*` 全空 → **该行不渲染**
  （无标题的歌单无法辨识，静默跳过，同 12a 的「异常条目不渲染」原则）
- **一致性**：`isSaved` 为 false 的条目若出现在响应里（后端脏数据）→ 不渲染，不「修正」数据

## 8. 边界与文案

- **截断**：标题 2 行（中文优先）；相对时间口径同 08 §8
- **极值**：>200 个收藏歌单 → 分帧渲染；全选 200 条批量取消限流（TG-32）
- **并发冲突**：
  - 在 06 取消收藏 → 返回本屏该行即时移除（共享本地态，不等下拉）
  - 左滑取消与多选取消同一行 → 先发起者胜，后者吞（12a 同规则）
  - 两个官方歌单同名 → 以 `id` 稳定次序，不做去重
- **零余额 / D12**：无下载/购买入口；06 的「播放全部」带来的扣费语义不在本屏出现
- **文案清单**（除 12a 共有项外新增）：`我的歌单` / `还没收藏歌单` /
  `在歌单广场点书签，就会出现在这里` / `去歌单广场` / `%d 个歌单` / `约 %d 首` / `收藏于` /
  `取消收藏` / `取消收藏没保存上，再试一次` / `%d 个没取消成功，已保留在列表` /
  `离线：歌单收藏需要联网` / `个` / `首`

## 9. 验收判据

- [ ] 排序按 `savedAt` 倒序，`savedAt` 缺失项落尾且相对顺序稳定（刷新两次结果一致）
- [ ] 摘要曲目数为「`trackCount` 之和（不去重）」，文案带「约」；`trackCount` 缺失项不计入
- [ ] 屏内**无**「新建歌单/编辑歌单/加入歌单」任何字样（v1.0 无端点）
- [ ] 06 取消收藏后返回本屏，行已消失；重新收藏后回 05 再收藏，本屏出现该卡（无需重启）
- [ ] 批量取消走逐条 DELETE（网络面板无契约外端点），部分失败保留勾选
- [ ] `title` 与 `titleCn` 全空的脏数据条目不渲染、不产生空白行、不显示错误

## 待裁决

1. **「约 M 首」是否可接受**：不去重求和会高估。若产品要求精确，需后端在
   `GET /api/saved-playlists` 提供去重后的并集计数（NEEDS 候选）。当前退路是删掉「约 M 首」
   只留「N 个歌单」→ **建议保留**（信息价值高于误差风险）。
2. **取消收藏是否需要二次确认**：本规格定为不需要（可逆）。若产品认为「收藏是用户资产」需确认，
   与 12a 批量取消一并加一次 Dialog（17-S7）。
