# 10 · 登录（邮箱 + 密码）

> G2 逐屏规格。基准 393×852pt。要点源：`inventory.md` 行 10。
> 数据源：`POST /api/auth/login` / `POST /api/auth/refresh` / `POST /api/auth/logout` /
> `GET /api/auth/me`（api-contracts §1）。凭证安全：D5 + AGENTS 硬边界 3。
> 通用态规范源：`17-state-gallery.md`。

## 1. 屏与上下文

- **层级**：**全屏 present**（`elevation.zOrder` dialog 层以下、覆盖内容层），不入导航栈。
  由受限入口以 modal 呈现；从 04 未登录卡片「登录」进入时同样为全屏 present。
- **入口**：① 17-S6 游客登录引导 sheet 的「邮箱登录」；② 04 底部卡片「登录」主钮；
  ③ 03/06/07 的收藏/加入队列等受限动作；④ 401 且 single-flight refresh 失败后的全局回落；
  ⑤ 15 设置登出后的再登录。
- **返回/关闭**：左上「✕」（**仅当本屏是以 modal 方式从可浏览上下文唤起时存在**；
  由 ④⑤ 强制唤起时无 ✕，只能登录或走「游客浏览」）。下滑手势允许（等价 ✕）。
- **互链**：成功 → 回到来处屏并**重放被拦截的那一次动作意图**（登录 intent CAS 防竞态，D5）；
  「游客浏览」→ 关闭本屏回落处；隐私/条款外链 → Safari。
- **与 04 的关系**：登录成功后不自动打开抽屉，只更新 04 底部卡片为已登录态。

## 3. 区块规格

- **整体容器**：底 `color.canvas`；内容列宽 = 屏宽 − 2×`spacing.xxl`（键盘升起时上移走系统避让）
- **A 关闭钮**：图标按钮 ≥44pt（TG-03），`color.secondary`
- **B 品牌位**：`design/assets/CovaAssets.xcassets` 官方图标，显示 64pt（TG-02/TG-05），
  上下留白 `spacing.xxl`；**禁止反色/重着色**（design/README 红线）
- **C/E 字段标题**：`type.subhead` / `color.secondary`，与输入框间距 `spacing.sm`；字段块之间 `spacing.lg`
- **D/F 输入胶囊**：高 50（TG-07）、圆角 `radius.capsule`、底 `color.surface`、
  内水平边距 `spacing.lg`；占位 `type.body` / `color.muted`；输入文本 `type.body` / `color.fg`
  - 默认描边：1pt `color.lineSubtle`（TG-04）
  - **focus**：描边 1pt `color.accent`（inventory 钉死 focus accent 描边）+ 底 `color.elevated`
  - 错误态描边：1pt `color.error`
  - 密码字段为安全输入（不透出明文），右侧可见切换 👁 图标按钮 ≥44pt 热区（TG-03）
- **G 行内错误位**：`type.subhead` / `color.error`，左侧 `exclamationmark.triangle` 符号（TG-18），
  与输入框间距 `spacing.sm`；**不**用 Toast、**不**用 Dialog（字段级可归因错误必须贴着字段）
- **H 主按钮**：高 50（TG-07）、`radius.capsule`、`gradient.brandButton` 底 + 白字 +
  `elevation.primaryButtonShadow`；宽 100%（内容列）；与 G/E 块间距 `spacing.xl`
  - 登录中：文字替换为菊花（白），按钮保持宽度不跳（inventory：登录中按钮转菊花），不可重复点
  - 不可用（邮箱/密码未填齐）：`color.muted` 底（components §10 禁用态），文字仍白
- **I 「游客浏览」**：文字按钮 `type.callout` / `color.accentText`，上下内边距扩至 ≥44pt 热区
- **J 分隔**：`color.lineSubtle` 1pt（TG-04），上下 `spacing.xl`
- **K 合规行**：`type.caption` / `color.muted`，居中，最多 2 行；《隐私政策》《服务条款》
  为 `color.accentText` 下划内联链接

## 4. 状态变体

- **加载**：本屏**无骨架**（纯本地表单）。唯一加载态 = 提交中（H 菊花）。
  提交超过 15s（api-contracts 超时）视为失败处理
- **空态**：不适用（表单无空态）。**禁**在密码未填时预先显示错误（首次失焦也不报错，
  只有提交才校验）
- **错误**（三种落点各有理由）：
  | 错误 | 落点 | 文案 |
  |---|---|---|
  | 字段级（格式不符/空） | G 行内 | `请填写邮箱` / `邮箱格式不对` / `密码至少 8 位` |
  | 凭证被拒（401） | G 行内（挂在密码位） | `邮箱或密码不正确`（**统一话术，不区分账号不存在/密码错**，防枚举） |
  | 传输/超时/5xx/解码失败 | 行内 + Toast 二者取一 → **行内**（保持表单与键盘状态） | `登录没成功，检查一下网络再试` |
  | 服务端要求验证（人机/风控） | 本屏不处理 | `这个账号需要网页端继续验证` + 外链 `covalink.cn`（v1.0 不内嵌 WebView） |
  - 401 后**不清空邮箱、清空密码**（保留用户主要输入、隐藏敏感输入）
- **离线**：提交前本地探测（或请求失败）→ G 行内「离线：登录需要联网」，不进入菊花态；
  表单内容保留
- **未登录（本屏自身）**：即默认态。**已登录时本屏不可达**：若被强制唤起（会话过期）
  → A 无 ✕、I「游客浏览」替换为「放弃并浏览」（效果 = 关闭并回落 guest）
- **NEEDS-1 未解锁的真实形态（必须能验收）**：`{token,refreshToken,expiresIn}` 已符合，但
  `user` 仅 `{id,email,name,role}` → 完整 `AuthUser` 解码失败。UI 降级：
  1. 登录**成功**（token 已入 Keychain）但 `user` 解码不完整 → 不得把用户踢回登录页、不得显「登录失败」；
  2. 落态为 authenticated + 「用户资料不全」的静默降级（04 G 区按 04 §7 规则显示 name/email、
     无 covaId、无余额）；
  3. 本屏不出现任何技术错误提示；
  4. 若客户端按严格 `AuthUser` 解码导致整个响应当失败 → **属实现缺陷**，§9 验收判据明禁
- **Reduce Motion**：present 动画（`motion.duration.page` 弹簧）→ 直接呈现；错误位出现/消失的
  高度动画退化为一帧；菊花保留（系统级指示，非装饰动效）；键盘避让走系统默认（不可关）

## 5. 深浅双主题差异

- 底 `color.canvas`、输入底 `color.surface`、focus 抬升为 `color.elevated` + `color.accent` 描边：
  全部双 mode token
- 深色下主按钮渐变与白字同值（`gradient.brandButton` 定义即保证对比度达标）
- 错误色 `color.error` 双主题同值；`color.accentText` 在 Dark 下为亮橙（tokens 双值），
  K 行链接无需另选色
- 图标（logo 资产）为官方不透明浅底资产 → **Dark 下不加底衬、不做反色**（红线）；
  若品牌位对比不足属资产层问题，登记 G4 前处理，不在本屏改
- **交付形态**：浅/深两版由 `color.*` mode 切换一次成对交付；**不存在**任何只在一套主题下成立的
  元素（品牌图标两主题同资产）

## 6. 可访问性

- **朗读顺序**：「登录，标题」→ ✕（可关时）→ 品牌图（**不朗读**，`accessibilityHidden`，
  品牌由屏幕标题承担）→「邮箱，文本字段」→「密码，安全文本字段」→「忘记密码，链接」→
  错误提示（**必须在密码字段之后**，并在出现时主动播报一次）→「登录，按钮」→「游客浏览，按钮」→
  合规行（含两个链接元素）
- 输入框标签与占位分离：placeholder 不作为 `accessibilityLabel`（避免输入后标签丢失）
- 密码可见切换：动态标签「显示密码 / 隐藏密码」，状态用 `isAccessibilityElement` + value
- **Dynamic Type**：AX 档下 B 品牌位缩至一档（`spacing.xxl`×1.5 上限，TG-05）；输入框高 50 →
  随文本自适应增大（不裁字）；K 行允许 3 行；主按钮文字不换行、宽度不变
- **触控目标 ≥44pt**：✕ / 两个输入框 / 👁 切换 / 忘记密码 / 主按钮 / 游客浏览 / 两个内联链接
  （内联链接行间距扩至 44 热区）

## 7. 数据契约

- **主请求**：`POST /api/auth/login`，body `{email, password}` → 期望 `{user, token, refreshToken, expiresIn}`
  - 密码字段在内存中为 `SecretString`（CovaCore 已按 TD-23 收口）；**不写日志、不入持久化**
  - token 对写 Keychain `ThisDeviceOnly`，按 principalId 绑定（D5）
- **成功后**：`GET /api/auth/me` → `{user, entitlements}`（NEEDS-3）拉余额/套餐；
  拉取失败不阻塞进入 App（按 04 §7 降级）
- **intent 重放**：登录前被拦截的动作以「登录 intent」形式携带（CAS 防竞态，D5），
  成功后由来处屏消费一次；失败（用户改主意/关闭）→ intent 丢弃，不留悬挂
- **refresh / logout**：`POST /api/auth/refresh`（single-flight）、`POST /api/auth/logout`
  不由本屏发起（15 设置与全局会话层负责）
- **不存在的端点（禁止发明）**：
  | 需求 | 契约状态 | v1.0 处理 |
  |---|---|---|
  | 注册 | `docs/api-contracts.md` §1 **无** `POST /api/auth/register` | 不提供 App 内注册；K 行之外增一行 `type.caption`/`color.muted`「还没有账号？请在 covalink.cn 注册」外链（**待 G2 验收确认**，见「待裁决 1」） |
  | 忘记密码 / 重置 | §1 **无** `forgot-password` / `reset-password` | 同上：E 行右侧「忘记密码?」为**外链**（Safari 打开官网），不是 App 内流程 |
  | Sign in with Apple | NEEDS-5（可选，v1.0 仅邮箱登录可豁免） | 本屏**不出现**第三方登录按钮（一旦出现即触发 Apple 强制要求，PLAN §2） |
  | 图形验证码/风控 | 无 | §4 错误表末行的外链兜底 |
- **可空规则**：`user.name` 空 → 后续屏按 04 §7 回落；`entitlements` 缺失 → 04/11/13 各自降级；
  `expiresIn` 缺失 → 视为短期 access token，按 401 驱动刷新（不本地推算过期）

## 8. 边界与文案

- **输入约束**：邮箱 trim + 小写归一后提交；密码原样（不 trim 中间空格，允许空格，最长 128 字符，
  超出即输入截断并 G 行内提示「密码太长」）
- **键盘**：邮箱 = `emailAddresses` 键盘 + 无自动大写；密码 = 关闭自动大写/自动纠错；
  「返回」键语义 = 下一字段，密码行「完成」= 提交
- **截断**：错误文案最长 1 行（超出时改用下方「文案清单」里的更短串，不做 `…` 截断），链接行 2 行
- **极值**：连续失败 5 次 → 按钮保持可用（限流由后端裁决），但 G 文案不变；
  第 6 次起在 H 下方追加一行 `type.caption`/`color.muted`「多次失败？可在网页端登录后再试」
- **并发**：本屏 present 期间底层屏不响应手势（模态）；重复唤起本屏 → 复用现有实例并复位表单错误态
- **零余额 / D12**：本屏不显示任何与 co 币、套餐、价格有关的内容（登录后才拉 entitlements）
- **文案清单**：`邮箱` / `密码` / `忘记密码?` / `登录` / `游客浏览` / `放弃并浏览` /
  `请填写邮箱` / `邮箱格式不对` / `密码至少 8 位` / `邮箱或密码不正确` / `登录没成功，检查一下网络再试` /
  `离线：登录需要联网` / `这个账号需要网页端继续验证` / `多次失败？可在网页端登录后再试` /
  `登录即同意《隐私政策》与《服务条款》` / `还没有账号？请在 covalink.cn 注册`

## 9. 验收判据

- [ ] 键盘升起时表单不被遮挡、错误位与主按钮均可点；收起键盘无跳动
- [ ] 401 时统一话术「邮箱或密码不正确」，**不出现**「账号不存在」或「密码错误」二分提示
- [ ] 日志与持久化中搜不到密码明文、token、任何 `Bearer` 串（门禁/评审取证项）
- [ ] NEEDS-1 未解锁时登录仍可用：token 入库、进入 authenticated，用户资料位静默降级，
      **不**被弹回登录页
- [ ] 从收藏动作唤起登录 → 成功后该收藏自动完成且只完成一次；取消登录后无悬挂意图
- [ ] 屏内**无**注册/忘记密码的 App 内流程（外链形态），**无**任何第三方登录按钮
- [ ] 「游客浏览」与 ✕ 两条退出路径行为一致；强制唤起（会话过期）时二者按 §1 规则出现
- [ ] VoiceOver 顺序与标签符合 §6；AX5 档下输入框与按钮不裁字

## 待裁决

1. **注册与找回密码的去向**：契约无端点。本规格选「外链官网」；若产品要求 App 内注册，
   需后端补 `register`/`forgot-password` 契约并重开本屏设计。
2. **键盘「完成」是否等于提交**：iOS 惯例是「下一字段」，两字段时也可直接提交 → 本规格钉
   「邮箱→下一字段；密码→提交」，**待 G2 验收确认**。
3. **会话过期强制唤起时是否保留「游客浏览」**：影响 guest 状态机（TD-30 记录了 guest 选择的
   owner 指针回滚问题）。本规格保留（改名「放弃并浏览」），实现须一并处理 TD-30 的回滚，
   **待协调者裁决**是否 M1 内解决。
