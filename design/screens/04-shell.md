# 04 · App 外壳（原生 TabView · 五页签含搜索位 · 每页签独立导航栈）

> G2 规格。基准 393×852pt。**2026-10-02 第二次重写**：在第一版外壳（四页签）之上
> 追加**第五页签「搜索」**（`Tab(role: .search)`，系统分隔位）——对齐 Apple Music iOS 26
> 的信息架构；首页改对话型首页（`01-home.md`），曲库 `.searchable` 迁入 25 搜索屏。
> 原「左侧抽屉」方案仍废除（2026-10-01 裁决不变：抽屉不符合 iOS HIG）。
> 色值/字号/间距/时长一律以 `../tokens.json` 的 token 路径引用；本文件不得出现裸字面量。
> 缺失 token 不自行新增，统一登记在文末「Token 缺口」。
> **闸门状态**：本文件是设计事实源，实现须等规格确认（AGENTS.md 硬边界 8）。

## 1. 外壳结构

- 外壳 = **原生 `TabView`**（iOS 26 `Tab` API），五个页签：首页 / 曲库 / 创作 / 我的 / 搜索。
  页签栏是**系统原生标签栏**（Liquid Glass、系统手势语义），不再自绘。
- **搜索页签用 `Tab(role: .search)`**：系统把它钉在标签栏右端、与其余四格分隔（Apple Music
  同款形态）；系统自带图标与「搜索」标题（传 nil 让系统给，不自造文案——「搜索」是系统词）。
- **每个页签各自持有一棵 `NavigationStack`**（各持各的 `path`）。搜索页签的栈根是 25 屏，
  栈内 push 的目标是**曲库列表复用件**（03 §7 的 `LibraryPreset` 形态，见 §3 归属表）。
- 迷你播放条 = **`tabViewBottomAccessory`**（系统承载位：原生标签栏正上方、随页签一起）；
  有播放任务才出现（§4）。搜索页签激活时 accessory 依然就位（系统行为，不接管）。
- 全屏播放器（02）/ 登录（10）/ 曲目详情（07）仍是**外壳级 sheet**，不属于任何页签栈。
- 抽屉**不存在了**：无左缘右滑开抽屉手势、无左上品牌钮、无遮罩层（§5 逐项给了去处）。

## 2. 页签（Tab）语义

| 页签 | 根屏 | 图标（SF Symbol） | 说明 |
|---|---|---|---|
| 首页 | `01-home` | `house` | 对话型首页：问候 + 生成/搜索切换 + 底置输入条 + 内容 feed（01 重写） |
| 曲库 | `03-library` | `music.note.list` | 级联筛选 + 曲目列表（搜索迁出至 25，03 §3 重写） |
| 创作 | `08-ai-sessions` | `sparkles` | 会话列表为根；19 创作台、09 会话详情、20 作品列表 push 其上 |
| 我的 | `11-mine` | `person` | 用户卡 + 余额/套餐 + 资产入口 + 商业入口 + 设置入口（insetGrouped） |
| 搜索 | `25-search` | 系统 `role:.search` 自带 | 搜索落地页（历史 + 分类浏览）+ 结果态（25 §2/§3） |

- 页签标题取自系统语义（`Tab` 的 title），**不**再做自绘 caption；搜索页签标题由系统
  `role` 提供，不写在标题清单里。
- 「创作」页签的图标/文字**不使用** `gradient.ai`（红线不变：AI 渐变只属各屏内的创作入口
  控件与 agent 文本，不含导航件）。页签着色 = 系统 tint，`color.accent`。
- **iOS 26 `Tab` API**：普通页签用 `Tab("首页", systemImage: …)`；搜索页签用
  `Tab(role: .search)`；选中态 = 系统 tint + `isSelected` trait（VoiceOver 念
  「首页，标签页，已选中」——系统自带，不自绘）。
- **点当前页签回到根**：页签栈非空时点已选中的页签 ⇒ pop 到该栈根（`path = []`）。
  已在根时再点 ⇒ 滚动到顶部（系统既有行为，不自造）。搜索页签同规则。
- **`tabBarMinimizeBehavior`**：`.onScrollDown` —— 向下滚动时标签栏自动收起为最小形态；
  回顶/上滑恢复。MiniPlayer（bottomAccessory）随栏一起最小化，不单独做收起逻辑。
- **页签顺序不可重排**、不开放 `TabView` 自定义页签集（无「更多」页签、无 Edit 页）。

## 3. 路由归属（每页签一棵栈）

- 屏内 push **默认进当前页签的栈**（`path.append` 的落点就是当前栈）。
- **深链 / 跨页签跳转**（通知点击、01 输入条提交、22→20、16→03 等）必须先把
  selection 切到目的页签、再把路由推进**那个页签的栈**；目的页签的既有栈
  先回根（不叠在旧屏上）。落到哪棵栈按这张归属表：

| 路由 | 归属页签 | 触发点 |
|---|---|---|
| `playlist(id)` | 首页 | 01 推荐歌单大卡 / 场景精选卡 / 05 网格卡 |
| `sharedPlaylist(token)` | 首页 | 01/05 分享歌单卡 |
| `plaza` / `plazaSearch(q)` | 首页 | 01「更多 ›」；01 搜索档目标=歌单的发送（05 §1） |
| `artist(id)` | 当前栈（01↔03↔25 各有入口，页签不切换） | 03 行 ⋯「查看艺人」/ 01 AI 音乐人头像 / 07 相似位 |
| `favorites` / `myPlaylists` / `myCreations` / `creditsLedger` / `membership` / `enterprise` / `settings` | 我的 | 11 各行（15 仅由 11 栈推入） |
| `aiSessions` / `aiSession(id)` / `studioCreate` / `worksList` | 创作 | 08 行 / 19「全部作品」/ 22「任务」链 / 01 生成档提交 |
| `library(preset)` | 当前栈（01↔03↔25 共用同一列表件） | 25 分类卡 / 01 搜索档目标=曲库的发送 / 01 场景卡 |
| 通知深链 `aiSession(id)` | 创作 | `handleNotificationTap`：切到创作页签 + 回根 + push |

- **`library(preset)` 是当前栈 push**：从 25 分类卡或 01 搜索档进入时，不切换页签，
  在发起栈内推「预填筛选的曲库列表」（03 §7 的 `LibraryPreset` 复用形态）——
  Apple Music 同理（搜索页签内点分类进的是该栈内的浏览页，不切到资料库页签）。
- 需要登录的目的地在游客态仍走 17-S6 登录引导 sheet，**不因页签化改变门槛**。
- 「歌单广场（05）」不是页签：它从 01「推荐歌单 › 更多」进入（首页栈内 push）。
  曲库屏**不**承担歌单入口（曲库 = 曲目语义）。
- **01 生成档提交** = 切到创作页签 + 回根 + push 09（对齐原「01 会话卡提交」归属，
  行为不变、发起控件换成 01 §4 的 `CovaComposer`）。

## 4. MiniPlayer（`tabViewBottomAccessory`）

- 内容规格沿用原 01 §7（封面 40 / 标题+艺人 / ⏯ / ⏭），落位为系统 bottom accessory。
- **无播放任务 ⇒ accessory 不存在**（不是隐藏 —— 标签栏恢复原高，不留空槽）。
- **无播放任务 ⇒ 全屏播放器不可打开**：accessory 是进入 02 的唯一入口；
  走查钩子 `COVA_PREVIEW_SHEET=player` 仅在快照有任务时生效（空队列时不 present）。
- 点 accessory 主体 → 02 全屏 sheet（外壳级，`elevation.zOrder` 不变）。
- 与 Toast 的层序：Toast 仍在内容区下缘、accessory 之上（17 §① 的 C5 修订位不变）。
- **iOS 26.0/26.1 分流**（2026-10-01 实测补记）：26.0 上空内容 accessory 自动收壳；
  26.1+ 必须传 `isEnabled:`（`snapshot?.item != nil`），否则画出空胶囊。分流在壳层做
  （`#available` 静态选分支，**TabView 身份不换边**——同一棵 `tabs` 视图上两套修饰符）。

## 6. 状态变体

- **游客**：首页/曲库/搜索页签照常（PRD 4.1；搜索是公开内容检索）；创作/我的页签根 =
  17-S6 引导形态（内容区显示「登录解锁创作与收藏」+ 渐变主钮「登录」+ 次要「先逛逛」，
  引导出现在页签内容区、不遮标签栏）。登录成功后停留在当前页签，不跳走。
  01 生成档发送在游客态 = 同一条 17-S6 引导（01 §4 钉死）。
- **登出**：`signOut` 完成后——五棵栈全部回根、selection 回首页、
  创作/我的页签回落游客形态；其余副作用按 D8（队列/缓存/owner 账）不变。
- **他端登出 / 401**：同「登出」回落（各栈回根 + 引导态），一次 Toast 说明。
- **Reduce Motion**：页签切换/标签栏收起/回根动画退化为一帧；bottomAccessory 的
  出现/消失无位移（一帧显隐）；`Tab(role:.search)` 的系统动效由系统自己处理
  reduce 语义，不干预。

## 7. 数据契约

外壳本身**不发请求**。`me`（余额/套餐/身份）由 11 负责（缓存口径 11 §7）；
外壳只读 `authPhase` 决定游客态与页签内容。**不为页签栏造徽标计数**（无契约支持，
同原资产计数条款的判法）。搜索页签的落地页数据（历史=本地、分类卡=taxonomy）由 25 屏
自取（25 §6），不经外壳转发。

## 8. 边界与文案

- **标签栏文案**：`首页` / `曲库` / `创作` / `我的`（4 个词固定，禁改）+ 系统「搜索」。
- **VoiceOver**：系统标签栏自带「标签页，已选中/未选中」朗读（iOS 26 的 Tab trait）；
  搜索页签系统念「搜索，标签页」。页签级元素不再额外加 trait。页签内导航语义由各屏 §6 负责。
- **AX 放大**：标签栏由系统自适应（iOS 26 下 AX3 内不溢出；更大档系统允许横向滚动
  或截断，不自造第二套布局）。页签内屏各自守自己的 AX 规则。
- **登录引导**：`登录解锁创作与收藏` / `登录` / `先逛逛`（沿用原清单，语义不变、
  落点换到页签根区）。
- **误触保护**：页签切换**不清**另一页签的栈；只有「点当前页签」才回根（§2）。
  搜索页签的「输入态 → 退出搜索回落地页」是系统 `.searchable` 行为，不算回根。
