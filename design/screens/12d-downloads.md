# 12d · 已下载（本地音频管理，D12 放行前隐藏）

> G2 逐屏规格。基准 393×852pt。要点源：`inventory.md` 行 12（同构四屏之一）。
> 骨架基线：`12a-favorites.md` §2–§6。数据源：`/api/downloads/checkout`、`/api/downloads/:id/file`
> （api-contracts §3）。**合规前提：D12 —— v1.0 无任何购买/充值入口，下载扣费 UI 入口待合规评审。**

## 1. 屏与上下文

- **层级**：push 自 11；入「我的」页签栈（04 §3）。
- **入口（放行后）**：① 11 我的 → 已下载行；② 15 设置「Wi-Fi 仅下载」行的副链接；
  ③ 深链 `downloads`。
- **互链**：行 → 播放（02，本地 `file://`）/ ⋯（删除本地文件 / 查看曲目 07 / 分享）；
  空态 CTA → 03 曲库；空间管理跳 15。
- **返回**：同 12a。
- **登录门槛**：需登录 + `entitlements.canDownload`（NEEDS-3）。
- **本屏的「隐藏策略」**（本轮硬要求，写死为三条）：
  | 门 | 判定 | 未满足时的表现 |
  |---|---|---|
  | 门 1 合规放行 | 全局开关 `downloadsUIEnabled`（构建期常量，由 D12 评审结论设定） | **整屏不施工路由出口**：04/11 的入口项**不渲染**、TrackRow ⋯ 与 07 的「下载」项**不渲染**、深链 `downloads` **静默回落 01 且无任何提示文案**（不出现「功能未开放」——那本身就是一块露出的入口） |
  | 门 2 能力 | `entitlements.canDownload == true` | 入口出现但行右侧值不渲染；本屏可进（只显已在本机的文件），新增下载的动作禁用 + 行内说明「当前套餐不支持下载」 |
  | 门 3 服务端开关 | `GET /api/downloads/checkout` 的 `enabled == true` | 结算确认页出现「下载暂时不可用」（`color.muted`）并禁用确认钮；本屏仍可查看本机已有文件 |
  三门**任一**不满足都不产生「灰着但可点」的入口——一律整项不渲染（对齐 04 §3.D、07 §3.F）。
  **v1.0（当前）= 门 1 未放行 → 本屏与全部入口在 shipped build 中不可达**；规格仍完整交付，
  以便放行当轮直接施工。

## 3. 区块规格

- **A 导航条**：`material.navGlass`；标题 `type.headline`；「编辑」同 12a §3.A
  （多选态动作 = 「删除本地文件」，**不是**「取消下载权」，文案严格区分）
- **B 空间卡**：`color.elevated` + 1pt `color.line`（TG-04）+ `radius.card`，内边距 `spacing.lg`
  - 「已用 X / 可用 Y」：`type.subhead` / `color.secondary`，数字 `type.mono`
    （数据源 = `FileManager` 属性，**非后端字段**，见 §7）
  - 条形：轨道 `color.surface`，填充 `color.accent`，高 4（TG-23）、圆角 `radius.capsule`，
    上下 `spacing.md`
  - 空间紧张（可用 < 单首平均大小的 5 倍）：文案转 `color.warning` + 行内提示「空间不太够了」
- **C Wi-Fi 仅下载开关**：`../components.md` §6 「深度思考 toggle」同族的胶囊开关
  （开 = `color.accent` 底 / 关 = `color.line` 底，文字 `type.subhead`），
  整行 ≥44pt（TG-03）；**状态与 15 设置为同一份本地偏好**（单一事实源，双向同步，见 §7）
- **D 下载中分组**（PRD 4.3 状态机：下载中 / 暂停 / 完成 / 失败）
  - 行：TrackRow 变体（高 64，封面 48）+ 第二行替换为「进度百分比 + 状态短语」（`type.caption` /
    `color.secondary`，`type.mono`）+ 轨道细条（`color.surface` 底 / `color.accent` 进度，高 4 TG-23）
  - 右侧两个图标按钮：暂停/继续（`pause.circle` / `play.circle`）、取消（`xmark.circle`），
    各 ≥44pt 热区（TG-03）
  - 失败行：状态短语 `color.error`「失败」+ 行内「重试」文字钮（`color.accentText`）
  - 分组标题「下载中（n）」`type.caption` / `color.muted`；无任务时整组不渲染
- **E 已完成列表**：TrackRow 原样（12a §3.C），差异：时长右侧加 `checkmark.circle` （`color.success`）
  表示已在本机；行点击 = 直接播本地文件（**不发网络**），MiniPlayer 显本地态
- **F 尾部状态行**：同 12a §3.D

## 4. 状态变体

- **加载（首访）**：B 卡轮廓呼吸（TG-24）；D 组不骨架（没有任务就没有组）；
  E 6 行 TrackRow 骨架。本机文件枚举是本地操作，通常在 `motion.duration.instant` 内完成，
  因此**首屏不应出现长骨架**——若出现即为实现把本地枚举放到了主线程之外的错误等待
- **空态**：无已完成且无进行中 → 17-S2：插画位 + 「还没有下载的歌」+
  「在曲库里点下载，就能离线听」(`type.callout`/`color.secondary`) + 主 CTA「去曲库」→ 03。
  B 空间卡**仍显示**（空间是本机事实，与列表空不空无关）
- **错误**：
  - 本机枚举失败（沙盒异常）→ 整屏错误态「读不到本机文件」+「重试」
  - 单个下载失败 → **行内**（该行「失败」+「重试」），**不** Toast 刷屏（批量下载时会有 N 条）；
    仅在用户主动取消/失败第一条时补一次 Toast「有 %d 首下载失败」
  - checkout/扣费失败 → 结算确认页行内（07/06 的下载动作流程内，不在本屏）
  - 全部失败（网络断）→ 顶部 17-S4 离线条「离线，下载已暂停」+ D 组全部转「等待 Wi-Fi」
- **离线**：E 已完成列表完全可用（可播、可删）；D 进行中全部挂起为「等待网络」（`color.muted`），
  不自动重试直到网络恢复；C 开关在离线时仍可改（本地偏好）
- **未登录 / 游客**：本屏不可达（门 2 之前的登录门槛，17-S6）；他端登出 →
  **保留已下载文件在沙盒但本屏数据视图清空**：D13/安全规格要求登出清私有音频与封面缓存（AGENTS §5、
  D8）——商用授权下载文件属「用户已购资产」还是「缓存」需裁决，本规格 v1.0 采「**一并清除并明说**」：
  登出二次确认里写「会清除已下载的文件」（15 §3 登出 Dialog 第 4 条），重新登录后需重新下载。
  → **待裁决 2**
- **Reduce Motion**：进度条数值更新保留（数据非装饰）但去掉滚动动画；行插入/移除的位移动画
  退化为一帧；条形宽度过渡关闭；D 组「等待 Wi-Fi」的呼吸点 → 静态文字

## 6. 可访问性

- **朗读顺序**：「已下载，标题」→ 编辑 → B 空间卡（「已用 412 兆，可用 6.8 GB」+
  条形**不**独立成元素，值已在标签内）→ C 开关（「只连 Wi-Fi 下载，开关，开启」）→
  「下载中，2 项」→ 每行「<曲名>，<艺人>，下载中 68%，暂停 按钮，取消 按钮」→
  「已完成，36 项」→ 每行「<曲名>，<艺人>，<时长>，已在本机，按钮」→（滑开）「删除本地文件，
  破坏性操作，按钮」
- 进度播报：行标签内含当前百分比；**不**随进度自动重复播报（只在聚焦时读当前值，09 §7 同规则）
- **Dynamic Type**：AX 档下 B 卡两行堆叠（已用 / 可用各一行）、C 开关整宽；D 行进度条与
  两枚按钮换到第二行（行高自适应）；E 行同 12a
- **触控目标 ≥44pt**：编辑 / 返回 / 开关整行 / 每行 / 暂停 / 取消 / 重试 / 删除本地文件 /
  空态 CTA / 重试钮

## 7. 数据契约

| 用途 | 端点 | 字段与说明 |
|---|---|---|
| 结算预览（放行后，07/06 发起） | `GET /api/downloads/checkout` | `{downloadCredits, balance, enabled, format:'mp3'}`；`enabled` = 门 3 |
| 结算/扣费 | `POST /api/downloads/checkout` `{trackIds[], format:'mp3', idempotencyKey}` | → `downloads[] / items[]`（`DownloadItemDto{trackId,downloadId,url,filename,owned}`）；`owned=true` 跳过重复扣费（D8 幂等键必带） |
| 取文件 | `GET /api/downloads/:downloadId/file` | 授权下载；**NEEDS-6 未解锁 → 不支持 Range → v1.0 无断点续传**（§8 并发） |
| 本屏「已下载」列表 | **本机沙盒清单为事实源** | 见下 |
| 空间占用 | 无端点 | `FileManager` 音量属性（`URLResourceKey`），**不是**后端字段，禁止包装成「服务端存储配额」 |
| Wi-Fi 仅下载 | 无端点（本地偏好，owner 绑定 D9） | 与 15 §3 同一份偏好键 |

- **列表事实源裁决（本屏最重要的一条）**：`docs/api-contracts.md` §3 **未记录**
  「下载记录列表」端点（只有 checkout 与 `/:downloadId/file`）。因此：
  1. E 已完成列表 = **本机沙盒存在且校验通过的文件** + 其本地元数据（`trackId` / `filename` /
     落盘时间）；曲目展示字段（标题/艺人/封面/时长）来自**落盘时缓存的 `TrackDto` 快照**
     （D9 Codable JSON，按 owner 分桶；封面走缓存图片）；
  2. **不得**为渲染列表去调 `POST /api/downloads/checkout`（那是**扣费写操作**，
     读列表绝不触发写）；
  3. 元数据缺失（旧文件/手改沙盒）→ 行仍显示，标题回落 `filename` 去扩展名，封面占位，
     ⋯ 菜单只留「删除本地文件」；
  4. 换设备/重装后列表为空是**预期行为**，空态文案不得承诺「云端可恢复」；
  5. 若产品要求「服务端下载历史」，需后端把 `GET /api/downloads`（列表）纳入契约 →
     **待裁决 1**（建议登记 NEEDS 候选 `DOWNLOADS-LIST`）。
- **NEEDS 关联（逐项显式）**：
  - **NEEDS-6 未解锁**：无 Range → UI 降级：不提供「断点续传」承诺；D 行「重试」=
    整首重新下载（进度从 0），并在首次重试时行内一句「会重新下载整首」
  - **NEEDS-3 未解锁**：`canDownload` 不可得 → 门 2 判定失败时**入口出现但动作禁用**
    （§1 表门 2 表现）；**不得**把「取不到能力」当「有能力」
  - **NEEDS-2 与本屏无关**；**D12**：门 1 未放行时本屏不可达，且 shipped build 中
    连字符串「已下载」都只存在于本规格文档，不出现在 UI 资源里（避免上架审查时被判定为
    隐藏的可付费下载入口）
- **可空规则**：`downloadCredits` 空 → 结算页费用行不渲染且确认钮禁用；`balance` 空 → 同上；
  `filename` 空 → 落盘名以 `trackId.mp3` 生成（本地兜底，不改后端）；`url` 为签名地址 →
  **不入日志、不入持久化索引**（TD-23 口径）

## 8. 边界与文案

- **截断**：曲名/艺人按 components §1；文件名（元数据缺失时）单行中段截断
- **零结果**：§4 空态（B 卡保留）
- **极值**：进行中任务 >5 → 队列上限（客户端并发 ≤3，其余「排队中」`color.muted`，TG-32）；
  已完成 >500 → 分帧渲染；单曲 >100 MB（长音频）→ 空间紧张提示提前触发
- **并发冲突**：
  - 同一曲目重复下载 → 行不重复创建，提示「已经在下载了」（`type.caption`/`color.muted`），
    结算侧由 `owned` 语义避免重复扣费（D8）
  - 暂停中删除 → 先取消传输（D16 有界取消：在途传输立即取消且结果不投递），再移除行
  - 空间不足导致写失败 → 该行「失败」+ 文案「空间不够了，清一清再试」并跳 B 卡提示
  - 下载中退后台：允许继续（`UIBackgroundModes` 目前只声明 audio；**下载后台续传需裁决** →
    待裁决 3），前台恢复时对账任务态（本地任务表 = 事实源）
- **零余额 / D12**：本屏**永不**出现「充值 / 余额不足请充值 / 价格」；余额只在
  07/06 的结算确认页出现一次（放行后），且本屏错误态不把余额话题带进来
- **文案清单**：`已下载` / `已用` / `可用` / `空间不太够了` / `只连 Wi-Fi 下载` / `下载中` /
  `等待网络` / `等待 Wi-Fi` / `排队中` / `暂停` / `继续` / `取消` / `失败` / `重试` /
  `已完成` / `已在本机` / `删除本地文件` / `还没有下载的歌` / `在曲库里点下载，就能离线听` /
  `去曲库` / `读不到本机文件` / `离线，下载已暂停` / `会重新下载整首` / `已经在下载了` /
  `空间不够了，清一清再试` / `当前套餐不支持下载`

## 待裁决

1. **服务端下载历史端点**：`GET /api/downloads`（列表）存在于线上实现但**不在本仓契约**
   （api-contracts §3 未记录）→ 本规格以本机为事实源。若需跨设备恢复列表，
   须先把它写进契约（NEEDS 候选 `DOWNLOADS-LIST`）。**不得**凭推测调用。
2. **登出是否清除已下载文件**：安全规格要求清「私有音频与封面缓存」（AGENTS/D8），
   而下载件是已授权资产。本规格采「清除 + 在登出 Dialog 明说」（15 §3）。
   另一选项 = 保留下载件、只清私有音频（需按 owner 分目录）。**待协调者裁决**。
3. **下载是否允许后台续传**：`Config/Info.plist` 目前只声明 `UIBackgroundModes: audio`。
   后台下载需新增 `background-fetch`/`background-sessions` 声明（属工程配置变更，非设计能定）→
   **待裁决**；v1.0 规格按「退后台即暂停、回前台继续」写。
4. **格式**：契约 `format:'mp3'` 单值 → 本屏不提供格式选择（未来若有多格式需重开此屏设计）。
