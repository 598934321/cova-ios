# 13 · 会员（权益展示 + App 内购买）

> G2 逐屏规格。基准 393×852pt。要点源：`inventory.md` 行 13。
> 合规（**D12 2026-10-01 修订**）：App 内购买只走 **StoreKit 2** + `/api/iap/verify` 核销
> （DEVELOPMENT.md §4.8）；**任何站外购买引导一律禁止**（由 `Scripts/d12-copy-check.sh`
> 词表机械执行，本屏是唯一经文件白名单允许出现购买词的文件）。
> 数据源：`GET /api/auth/me` → `entitlements`；`GET /api/iap/products`（商品镜像）；
> StoreKit 2 `Product.products`（价格与可买面）；`POST /api/iap/verify`（核销）。
> **核销纪律**：verify 200 才 `transaction.finish()`；402/400 → finish + 告知；
> 401/503/网络 → **不 finish**，留 `Transaction.updates` / 启动重验。

## 1. 屏与上下文

- **层级**：push 自 11 我的「会员权益」行；入「我的」页签栈（04 §3）。
- **入口**：① 11「商业」组「会员权益」；② 深链 `membership`。
- **互链**：购买区卡 → StoreKit 2 `purchase()`（系统支付 sheet，App 不内嵌任何购买网页）；
  「恢复购买」→ `AppStore.sync()` + 逐条 `Transaction.latest(for:)` 重验；
  「企业服务」文字钮 → push 14（不外跳）；法务两链（隐私政策/服务条款）→ Safari。
- **返回**：退栈回来源。**关闭路径唯一**：本屏无「放弃/关闭」按钮，靠导航返回。
- **登录门槛**：**游客可看商品与权益介绍**（权益介绍是公开信息）；
  点购买/恢复 ⇒ 弹登录（`requireLoginForCollections()`，10 屏），购买只在已登录发生
  （核销要 `userId`）。当前套餐高亮只在登录后出现。

## 3. 区块规格

- **A 导航条**：`material.navGlass`；标题 `type.headline`；返回 ≥44pt（TG-03）
- **B 我的套餐卡**（仅登录且 `entitlements.plan` 可得时渲染）：
  - 底 `color.memberGoldSoft`，1pt `color.memberGoldBorder` 描边（TG-04），圆角 `radius.card`，
    内边距 `spacing.lg`
  - 套餐名 `color.memberGold` / `type.headline`（四档中文见 11 §8 唯一源）
  - 副行：`entitlements.activeUntil` → 「有效期至 YYYY年M月D日」`type.caption` /
    `color.memberGold`；free 档无有效期 → 该行不渲染（不留空）
  - **卡内无任何按钮**；整卡不可点（与 11 §3.C 同规则：展示不可点是有意的）
  - 未登录 → 整卡不渲染（不出现「登录后查看」的引导卡，那等于把 CTA 换了个名字）
- **C 权益对比表**：
  - 容器：横向可滚，左右起于 `spacing.pageGutter`；首列（权益名）冻结，宽 = 屏宽 × 42%（TG-01）
  - 表头列：套餐名 `type.callout` / `color.memberGold`；**当前套餐列**额外加 2pt
    `color.fg` 顶边（TG-04）+ 列底 `color.selectedBg`（登录后可得——web v2.65.0
    去橙化，当前项用中性高亮不用橙，见 design/README「与 web 的统一设计语言」）
  - 行：权益名 `type.subhead` / `color.fg`（左，1–2 行）；取值单元格 `type.caption` /
    `color.secondary`，✓ 用 `color.memberGold`、✕ 用 `color.muted`（**不用** `color.error`——
    缺能力不是错误）；行高最小 44（TG-19）；分隔 `color.lineSubtle` 1pt
  - 数值一律 `type.mono`（额度类）；「定制」等文字值同字号
  - **不渲染价格行**（D12，见「待裁决 3」）
- **D 说明区**：`type.callout` / `color.secondary`，左右 `spacing.pageGutter`，
  最多 4 行；文案固定（§8）
- **E 企业服务钮**：**文字按钮**（`type.callout` / `color.accent`）→ push 14
  （站内路由，不再外跳官网——D12：站外购买引导禁绝，企业服务本身在 App 内有屏）。
- **G 购买区（订阅 + co 包，StoreKit 2）**：
  - **商品对齐**：`GET /api/iap/products` 给镜像（productId / type / displayName /
    priceDisplay），`Product.products()` 给可买面与**本地价**；两源按 productId 对齐，
    **未对齐的镜像行不渲染**（点了买不了的卡比没有卡更坏），屏上价格一律取
    `Product.displayPrice`（镜像 `priceDisplay` 只在 ASC 缺商品时作**兜底文案**，
    且该行不渲染购买钮——价都拿不到就谈不上买）。
  - **卡**：每档一行/一卡，卡内 = 名称 + 周期或 co 数 + 价格 + 「购买」钮（`CovaButton`）。
    订阅卡标「每月/每年」，co 包标「一次性」。当前套餐档位的订阅卡**不重复画购买钮**
    （`canSubscribe` 语义：已在 creator 档不买 creator.monthly）。
  - **购买态**：在途 → 卡内钮换进度环、整卡不可再点；`purchase` 返回 `.pending`
    （家长审批等）→ Toast「已提交，待审批」；`.userCancelled` → 静默回卡态；
    verify 200 → `transaction.finish()` + `loadMe(force: true)` 刷权益 + Toast「已到账」；
    verify 402/400 → finish + Toast 告知核销被拒（附「请联系客服」）；verify 401/503/
    网络 → **不 finish**，Toast「购买成功，权益稍后到账」，凭证留待
    `Transaction.updates` / 下次启动重验。
  - **F 合规区（必须有）**：「恢复购买」钮 + 「隐私政策」「服务条款」两条法务外链 +
    一句「购买即代表同意《服务条款》与《隐私政策》」。三条缺一不可（D12 门禁逐字扫）。

## 4. 状态变体

- **加载**：B 卡与 C 表同原规格（无骨架，`me` 到位前不高亮）。G 区例外：商品镜像 +
  `Product.products` 两趟异步 ⇒ 购买区先骨架（`CovaSkeleton` 3 行），镜像或 ASC 任一
  失败 → 购买区**整块不渲染**（不是画一排买不了的卡），F 合规区照常。
- **错误**：`me` 失败 → 静默（同上）。购买失败态落 Toast（不重画区）；
  verify 402 系**核销被拒**话术，与「网络没通」严格分开（前者 finish 不再来，后者会再来）。
- **离线**：静态区照常；购买区整块不渲染（StoreKit 拉不到价）。B 卡缓存 + 「未同步」照旧。
- **未登录 / 游客**：无 B 卡、C 表无当前列高亮；G 区商品照常可见，
  点购买/恢复 → 弹登录。核销从来不发给游客。
- **Reduce Motion**：同原规格；购买在途环不退化（真实进度件）。

## 5. 深浅双主题差异

- 金色系完全由 `color.memberGold / memberGoldSoft / memberGoldBorder` 的 mode 值承担
  （Light 深金字浅金底 / Dark 亮金字深金底）——**本屏禁止出现任何自造金色**
- 表体底 `color.canvas`、当前列底 `color.selectedBg`（两主题各自值）
- `color.muted`（✕）在 Dark 下更暗但仍可读，符合「弱化不可用」的层级意图
- E 文字钮 `color.accentText` 双值保证对比度 ≥4.5:1

## 6. 可访问性

- **朗读顺序**：「会员权益，标题」→ 返回 →（B）「当前套餐，创作版，有效期至 …」→
  C 表以**表格语义**呈现：列头「免费 / 创作版 / 专业版 / 企业版」+ 每行
  「<权益名>，免费 <值>，创作版 <值>，专业版 <值>，企业版 <值>」
  （用可导航的表格容器，支持转子逐列朗读；**不**做成一堆静态 Text；
  额度类行在 2026-10-01 C4 后整行不存在 ⇒ 朗读序列里也没有它）
- ✓/✕ 符号必须有语义替代：朗读「支持」/「不支持」，符号本体 `accessibilityHidden`
- D/E/F 依次朗读；E 标签「前往官网了解，链接，将在系统浏览器中打开」
- **Dynamic Type**：AX 档下 C 表改为**逐套餐纵向卡片**（每套餐一张卡：标题 + 权益名:值 列表），
  放弃横向对比 —— 因为放大字号后横向表必然溢出；首列冻结逻辑在卡片形态下不存在
- **触控目标 ≥44pt**：返回 / E 外跳 / 表格行（本屏行不可点，无目标要求）；
  唯一硬要求是 E 与返回 ≥44

## 7. 数据契约

| 用途 | 端点 / 来源 | 字段 |
|---|---|---|
| 当前套餐 / 有效期 / 能力 | `GET /api/auth/me` → `entitlements` | `plan`、`activeUntil`、`canDownload`、`canUseCovaAI`、`canRequestProjects` |
| 权益表内容 | **无端点** | 见下 |
| 商品镜像 | `GET /api/iap/products` | `{products[]}`：`productId` / `type`（`subscription\|credits`）/ `displayName` / `priceDisplay` |
| 可买面与本地价 | StoreKit 2 `Product.products` | 镜像↔ASC 按 `productId` 对齐；价格以 `displayPrice`（StoreKit）为准 |
| 核销 | `POST /api/iap/verify` | `{transactionId, productId, jwsTransaction}`；200 = 核销+权益；幂等由 `transaction_id` UNIQUE 承担（**不带客户端幂等键**） |
| 恢复购买 | `AppStore.sync()` + `Transaction.latest(for:)` | 逐条重验；不复用任何缓存态 |

- **权益表内容 = 本地静态常量**：`docs/api-contracts.md` **没有**套餐/定价/权益端点
  （定价能力只存在于官网）。因此本屏表格内容由 App 内常量表提供，常量表**必须**：
  1. 以 `plan` 四档为列（与 `CovaPlan` 枚举严格同集，不增不减）；
  2. 每格取值只能引用 `entitlements` 里真实存在的布尔/枚举能力（`canDownload` / `canUseCovaAI` /
     `canRequestProjects`）；额度类行（如「每月额度」）**在没有任何真实数据源时整行不渲染** ——
     2026-10-01 C4 修订：四格「—」等于印了一行"我们知道有额度但什么都没有"，
     没有数据就该没有这一行；原写法「四格 — + 『额度以官网为准』脚注」随之作废（脚注拆除）
     → 见「待裁决 3」（这是本屏最容易被写歪的地方：把 web 的价目表搬进 App 就是引入价格信息）；
  3. 常量表在文件头注明「源：covalink.cn 官网套餐说明，日期」，G4 提审前须复核一次。
- **`monthlyCredits`**：契约有此字段（数字）。是否可在表格里逐档展示？→ 不能：
  它是**当前用户**的额度，不是各档定义值。本屏只用它做「当前档位」的**旁证**（B 卡副行不显，
  11 §7 待裁决 3 同口径），表内数字仍属静态常量问题 → 「待裁决 3」。
- **NEEDS 关联**：NEEDS-3 未解锁 → `entitlements` 不可得 → B 卡与当前列高亮不渲染。
  **§7 #56 核销链服务端缺口**（验签未接）：verify 必然 402/503 ⇒ 购买真实会到
  「购买成功、核销被拒/待核」那一格，整链路**灰度内测**内有效，上架前阻塞（#56）。
- **不消费的字段**：`subscriptionId`（契约建模有，但展示订阅标识会牵出「管理订阅」期待 → 不展示）
- **可空规则**：`activeUntil` 空 → 副行不渲染；`plan` 空 → B 卡不渲染；
  `canDownload=false` → 表格该格「不支持」（不隐藏该行，让用户知道能力存在）；
  镜像有 productId 但 ASC 没有 → 该档不渲染购买钮（见 §3.G）

## 8. 边界与文案

- **套餐四档中文**：免费版 / 创作版 / 专业版 / 企业版（唯一源 11 §8）
- **站外引导禁词（全仓硬约束，门禁机械执行）**：`前往官网` `官网了解` `官网核对` `官网完成`
  `App 内不售卖` `未在 App 内` `需在官网` `请前往` → 一律**不得**出现在任何文件的字面量里。
- **购买词白名单**：`购买` `订阅` `恢复购买` `价格` `¥` `元/月` `支付` `充值` `付款`
  `立即开通` `下单` `优惠` `限时` `免费试用` `报价` `立即签约` —— **只允许**出现在
  本屏承载文件（`MembershipAndEnterprise.swift`，门禁白名单登记）内；
  其它任何文件出现即违例（含 VoiceOver 标签）。
- **允许措辞**：`会员权益` `当前套餐` `支持` `不支持` `定制` `了解企业服务` +
  购买区：`购买` `恢复购买` `每月` `每年` `一次性` `已提交，待审批` `购买成功，权益稍后到账`
  `已到账` `隐私政策` `服务条款` `购买即代表同意《服务条款》与《隐私政策》`
- **截断**：权益名 2 行；表头套餐名单行；D 区 4 行；商品名 1 行截断（`displayName` 服务端给）；
  价格不截断（`displayPrice` 一行）
- **极值**：权益行 >12 → 表内滚动（纵向）；列 >4 → 不允许（枚举固定四档）；
  镜像 >7 档 → 全渲染（服务端加档自动出现）；ASC 缺档 → 只缺那一档
- **并发**：`me` 与 11/04 共享缓存；`Product.products` 与镜像各只取一次（`.task`），
  购买在途行内禁用；`Transaction.updates` 监听挂在会话生命周期上，不随屏重建
- **文案清单**：`会员权益` / `当前套餐` / `有效期至` / `未同步` / `支持` / `不支持` /
  `定制` / `这些不含在套餐里` / `定制合作与批量授权走企业服务，App 内不办理。` /
  `了解企业服务` / `订阅` / `co 包` / `购买` / `恢复购买` / `每月` / `每年` / `一次性` /
