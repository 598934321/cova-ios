# 13 · 会员（权益展示，无购买）

> G2 逐屏规格。基准 393×852pt。要点源：`inventory.md` 行 13。
> 合规：**D12 —— v1.0 不含任何购买/充值入口，仅展示余额**（AGENTS 硬边界 9）。
> 数据源：`GET /api/auth/me` → `entitlements`（api-contracts §1）。
> **本屏不出现：价格、下单、支付、订阅管理、「立即开通」、余额充值。**
> 通用态规范源：`17-state-gallery.md`。

## 1. 屏与上下文

- **层级**：push 自 04 抽屉「会员」/ 11 我的「会员权益」行；入导航栈。
- **入口**：① 04 商业组「会员」（memberGold 调）；② 11 F 组「会员权益」；③ 深链 `membership`。
  两处入口在 **v1.0 均可见**（展示权益不是购买入口，D12 不禁止「介绍自家套餐」；
  但入口文案必须用「权益」而非「开通/升级」——见 §8 文案清单与「待裁决 1」）。
- **返回**：退栈回来源。**关闭路径唯一**：本屏无「放弃/关闭」按钮，靠导航返回。
- **互链**：底部「前往官网了解」→ Safari（系统浏览器，**不内嵌 WebView**，见「待裁决 2」）；
  「查看当前套餐权益」锚点滚动到本屏对应列，不外跳。
- **登录门槛**：**无**。游客可看（权益介绍是公开信息）；当前套餐高亮只在登录后出现。

## 3. 区块规格

- **A 导航条**：`material.navGlass`；标题 `type.headline`；返回 ≥44pt（TG-03）
- **B 我的套餐卡**（仅登录且 `entitlements.plan` 可得时渲染）：
  - 底 `color.memberGoldSoft`，1pt `color.memberGoldBorder` 描边（TG-04），圆角 `radius.card`，
    内边距 `spacing.lg`
  - 套餐名 `color.memberGold` / `type.headline`（四档中文见 11 §8 唯一源）
  - 副行：`entitlements.activeUntil` → 「有效期至 YYYY年M月D日」`type.caption` /
    `color.memberGold`；free 档无有效期 → 该行不渲染（不留空）
  - **卡内无任何按钮**；整卡不可点（与 11 §3.C 同规则：展示不可点是有意的）
  - 未登录 → 整卡不渲染（不出现「登录后查看」的引导卡，那等于把 CTA 换了个名字）
- **C 权益对比表**：
  - 容器：横向可滚，左右起于 `spacing.pageGutter`；首列（权益名）冻结，宽 = 屏宽 × 42%（TG-01）
  - 表头列：套餐名 `type.callout` / `color.memberGold`；**当前套餐列**额外加 2pt
    `color.accent` 顶边（TG-04）+ 列底 `color.accentSoft`（登录后可得）
  - 行：权益名 `type.subhead` / `color.fg`（左，1–2 行）；取值单元格 `type.caption` /
    `color.secondary`，✓ 用 `color.memberGold`、✕ 用 `color.muted`（**不用** `color.error`——
    缺能力不是错误）；行高最小 44（TG-19）；分隔 `color.lineSubtle` 1pt
  - 数值一律 `type.mono`（额度类）；「定制」等文字值同字号
  - **不渲染价格行**（D12，见「待裁决 3」）
- **D 说明区**：`type.callout` / `color.secondary`，左右 `spacing.pageGutter`，
  最多 4 行；文案固定（§8）
- **E 外跳动作**：**文字按钮**（`type.headline` / `color.accentText`），整行高 ≥44pt，
  无底色、无渐变、**不用主按钮样式**（主按钮 = 转化设计，合规上等价于购买入口）；
  右侧 `arrow.up.right.square`（`color.muted`）
- **F 合规脚注**：`type.caption` / `color.muted`，居中，上下 `spacing.xl`，
  **必须逐字存在**：「套餐说明以官网为准，App 内不售卖」

## 4. 状态变体

- **加载**：本屏主体为静态内容 → **无骨架**。唯一异步件 = `me`：B 卡与 C 表当前列高亮
  在数据到位前**不渲染**（先显无高亮的表，数据到后再点亮），不做「加载中」占位
- **空态**：不适用（内容恒有）。C 表若因数据源问题一行都没有 → 整表不渲染，只留 D/E/F
- **错误**：`me` 失败 → 静默（按 §5 无高亮态渲染），**不**弹 Toast、**不**出现错误屏
  （本屏不是交易屏，取不到套餐不影响阅读）。唯一例外：离线时 E 外跳仍可点（Safari 自会处理）
- **离线**：主体照常（本地静态内容）；B 卡若有缓存则显缓存 + 「未同步」（`color.muted`，11 同规则）
- **未登录 / 游客**：无 B 卡、C 表无当前列高亮、其余完全一致；E/F 照常
- **Reduce Motion**：横向滚动为系统滚动；当前列点亮的淡入（`motion.duration.fast`）→ 一帧到位；
  push 转场退化为一帧

## 5. 深浅双主题差异

- 金色系完全由 `color.memberGold / memberGoldSoft / memberGoldBorder` 的 mode 值承担
  （Light 深金字浅金底 / Dark 亮金字深金底）——**本屏禁止出现任何自造金色**
- 表体底 `color.canvas`、当前列底 `color.accentSoft`（两主题各自值）
- `color.muted`（✕）在 Dark 下更暗但仍可读，符合「弱化不可用」的层级意图
- E 文字钮 `color.accentText` 双值保证对比度 ≥4.5:1

## 6. 可访问性

- **朗读顺序**：「会员权益，标题」→ 返回 →（B）「当前套餐，创作版，有效期至 …」→
  C 表以**表格语义**呈现：列头「免费 / 创作版 / 专业版 / 企业版」+ 每行
  「每月创作额度，免费 30，创作版 200，专业版 800，企业版 定制」
  （用可导航的表格容器，支持转子逐列朗读；**不**做成一堆静态 Text）
- ✓/✕ 符号必须有语义替代：朗读「支持」/「不支持」，符号本体 `accessibilityHidden`
- D/E/F 依次朗读；E 标签「前往官网了解，链接，将在系统浏览器中打开」
- **Dynamic Type**：AX 档下 C 表改为**逐套餐纵向卡片**（每套餐一张卡：标题 + 权益名:值 列表），
  放弃横向对比 —— 因为放大字号后横向表必然溢出；首列冻结逻辑在卡片形态下不存在
- **触控目标 ≥44pt**：返回 / E 外跳 / 表格行（本屏行不可点，无目标要求）；
  唯一硬要求是 E 与返回 ≥44

## 7. 数据契约

| 用途 | 端点 | 字段 |
|---|---|---|
| 当前套餐 / 有效期 / 能力 | `GET /api/auth/me` → `entitlements` | `plan`（`free|creator|pro|enterprise`）、`activeUntil`、`canDownload`、`canUseCovaAI`、`canRequestProjects`、`monthlyCredits` |
| 权益表内容 | **无端点** | 见下 |

- **权益表内容 = 本地静态常量**：`docs/api-contracts.md` **没有**套餐/定价/权益端点
  （定价能力只存在于官网）。因此本屏表格内容由 App 内常量表提供，常量表**必须**：
  1. 以 `plan` 四档为列（与 `CovaPlan` 枚举严格同集，不增不减）；
  2. 每格取值只能引用 `entitlements` 里真实存在的布尔/枚举能力（`canDownload` / `canUseCovaAI` /
     `canRequestProjects`），额度类数字（「每月 30/200/800」）在无契约来源时
     **不写具体数字，改写「—」并在 D 区注明「额度以官网为准」**
     → 见「待裁决 3」（这是本屏最容易被写歪的地方：把 web 的价目表搬进 App 就是引入价格信息）；
  3. 常量表在文件头注明「源：covalink.cn 官网套餐说明，日期」，G4 提审前须复核一次。
- **`monthlyCredits`**：契约有此字段（数字）。是否可在表格里逐档展示？→ 不能：
  它是**当前用户**的额度，不是各档定义值。本屏只用它做「当前档位」的**旁证**（B 卡副行不显，
  11 §7 待裁决 3 同口径），表内数字仍属静态常量问题 → 「待裁决 3」。
- **NEEDS 关联**：NEEDS-3 未解锁 → `entitlements` 不可得 → B 卡与当前列高亮不渲染，
  本屏退化为纯静态介绍页（这是**正确的降级**，不是缺陷）。NEEDS-1 未解锁 → `plan` 缺 → 同上
- **不消费的字段**：`subscriptionId`（契约建模有，但展示订阅标识会牵出「管理订阅」期待 → 不展示）
- **可空规则**：`activeUntil` 空 → 副行不渲染；`plan` 空 → B 卡不渲染；
  `canDownload=false` → 表格该格「不支持」（不隐藏该行，让用户知道能力存在）

## 8. 边界与文案

- **套餐四档中文**：免费版 / 创作版 / 专业版 / 企业版（唯一源 11 §8）
- **禁词表（本屏硬约束，评审据此攻击）**：`购买` `充值` `支付` `立即开通` `升级` `订阅管理` `付款`
  `价格` `¥` `元/月` `限时` `优惠` `恢复购买` → 一律**不得**出现在文案、VoiceOver 标签、图片 alt 中
- **允许措辞**：`会员权益` `套餐说明以官网为准，App 内不售卖` `当前套餐` `前往官网了解`
  `支持` `不支持` `定制`
- **截断**：权益名 2 行；表头套餐名单行；D 区 4 行；F 脚注 2 行
- **极值**：权益行 >12 → 表内滚动（纵向）；列 >4 → 不允许（枚举固定四档）
- **并发**：本屏与 11/04 共享 `me` 缓存，任一处刷新三处同步；不产生独立请求
- **文案清单**：`会员权益` / `当前套餐` / `有效期至` / `未同步` / `前往官网了解` /
  `套餐说明以官网为准，App 内不售卖` / `支持` / `不支持` / `定制` / `额度以官网为准` /
  `这些不含在套餐里` / `下载与扣费入口目前未在 App 内开放，请在官网了解与使用。`
