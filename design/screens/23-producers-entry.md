## 1. 屏与上下文

- **交付形态**：创作输入「+」面板展开后，位于面板**顶部**的一组「制作人卡」（纵向排列，
  非横滑——非空时的条目数未知，横滑会把不可读的长文推到屏幕外）。
  本屏规定：面板里有什么、卡上有什么、以及**空列表时面板里必须没有这个区**。
- **层级**：无层级（面板是宿主输入卡的一部分）；深链 `producers` **不建立**
  （一个默认不可见的东西没有可直达的目的地；建了就是一个假入口）。
- **入口 = 创作输入「+」钮**：位置在 01 §2 会话输入卡第二行（模式 chips 与「深度思考」同一行）
  的最左端，与 09 §J 的同一组件同位（两处共用一个组件 ⇒ 一个钮）。
  **宿主面尚未存在**：`01-home.md` §2 与 `09-ai-session-detail.md` §J 都只有
  「找歌 / 做歌 / 深度思考」，**没有「+」**（`03-library.md` 的「+」是筛选维度展开，不是同一物）
  ⇒ 本屏把「+」面板本体钉在 §3.A，并在 `inventory.md` 行 01/09 登记**待回写的交叉引用**；
  本任务不改这两屏（01/02/03 为 G1 已产出物，改动需验收；09 由其持有者回写）。
- **互链**：**无**。P2 阶段的制作人卡是**只读展示**——可点的动作
  （进入制作人会话 / 提交需求 / 领取交付）全部落在 `POST /api/studio/producers/projects`
  与 `GET/POST /api/studio/producers/:id/actions|surveys`，而契约 §4.6 明写这三条属 **P3** ⇒
  今天没有任何合法落点 ⇒ **不渲染 `chevron.right`、不渲染任何钮、卡不可点**
  （理由不是「没做」，是「无目标」，与 20 的分享钮同一族的判断）。
- **返回**：随宿主面板关闭（下滑 / 点遮罩 / 「+」再点一次收起）。
  **登录门槛**：面板在创作输入卡内，游客点创作会被 17-S6 拦在面板之外 ⇒ 制作人卡
  **今天只在登录态可见**；该端点是否接受匿名 ⇒ 「待答（1）」。
- **与其它屏的关系**：与 20/21/22 无数据交集（不产作品、不扣 co、不记账）。
  它是手册 §5 P3「producers 全流程」的**唯一 P2 前置**，作用是把「服务端有没有开这个能力」
  变成客户端一个可判定的可见性开关，而不是把整套流程提前做完。

## 3. 区块规格

- **A 「+」钮**：圆形 40（TG-07）+ `plus` 符号（`color.secondary`），与发送钮同一排同一规格；
  ≥44pt 热区（TG-03）。点按展开/收起面板（`motion.duration.normal` + `motion.curve`）。
  **本钮常驻**（不因 producers 为空而不渲染）——它是输入卡的能力面，不是制作人的入口；
  把它做成「仅非空时出现」会让面板永远没有入口（先有鸡还是先有蛋），这是刻意的分工：
  **入口常驻，内容按服务端事实显隐**。
- **B 面板容器**：`color.elevated` + 顶部 `radius.hero` + 拖拽指示条（TG-16）；
  高 = 屏高 60% → 92% 两档吸附（TG-15）、AX 档近全屏（07 §6 同规则）；
  内边距 `spacing.pageGutter`；**面板内不出现 MiniPlayer 之上的浮动件**（z 序见手册 §3.5 的
  overlay 层，本面板属 overlay 层）。
- **C 分组标题**：「制作人」`type.caption` / `color.muted`，左右 `spacing.pageGutter`，
  下 `spacing.md`。**只有 `producers.length > 0` 时才存在**（12c §3.F 的「不留空标题」同判据）。
  标题**不**用 `gradient.ai` 着色（AI 渐变只用于创作入口与 agent 文字，04 §3.B 红线；
  本区不是入口也不是 agent 发言）。
- **D 制作人卡**：`color.surface` 底 + `radius.card` + 内边距 `spacing.lg`；卡间距 `spacing.md`；
  **不可点**、无按压态、无 `chevron`；`../components.md` 缺位（该文件已随旧手册删除，
  见 `inventory.md` 通用要求）⇒ 卡的几何在本屏自钉，**不**引用不存在的组件档。
- **E 卡头 `displayName`**：`type.headline` / `color.fg`，1 行截断（AX 2 行）。
  **原样上屏**：服务端给的中文名，iOS 不加「制作人」前缀、不「统一称谓」。
- **F `tagline`**：`type.callout` / `color.secondary`，2 行截断。缺失 ⇒ 该行不渲染。
- **G `stages[]` 步骤列表**：分组小标题「步骤」（`type.caption` / `color.muted`）；
  每条一行：序号（`type.mono` / `color.muted`，序号由**数组下标 +1** 得出，契约无 `order` 字段）+
  `label`（`type.subhead` / `color.fg`）+ `summary`（`type.caption` / `color.muted`，
  收起 2 行 + 「展开」文字钮，`color.accentText`，≥44pt 热区）。
  条目顺序 = 响应数组顺序，客户端**不重排**（`stages[].id` 未说明用途 ⇒ 不做本地排序键）。
  `stages` 为空数组 ⇒ G 段连同「步骤」标题不渲染。
- **H `deliverables` / I `extensions`**：各为一段 chips 流（分组小标题「交付物」/「可延展」，
  同 C 档字号）；chip 高 36（TG-07）、`color.elevated` 底 + 1pt `color.line` 描边（TG-04）、
  `type.caption` / `color.secondary`，多行 wrap，最多 3 行 + 「+N」（07 §3.G 同族，点开=展开全部）。
  - **chip 的文字 = 条目的 `label`**；条目是**对象**（`{kind, label, required, description}`，
    端侧建模见 §7 末）：`kind` 是分类视图**不外露**、`description` 收进展开态、
    `required` 只做次级标记（见下条）。
  - **`required` 为 `nil` ⇒ 什么都不显示**。它是「服务端没说这句话」，
    渲染成「非必须」等于替服务端说话（同一族的判据来自并行建模的 DTO 注释，
    规格侧把它升格为硬规则）。本屏**不**加「必选 / 可选」胶囊，直到 §4.7 补出实测卡。
  - 解码容忍：字符串 → 直接用；对象 → 取 `label`；两者都取不到 ⇒ **该条不渲染**；整段取不到 ⇒ 整段不渲染。
  - 两段皆空 ⇒ 两段标题一并消失。
- **不渲染的字段**（§7 逐条给理由）：`fictional`、`audience`、`greeting`、`demoCount`、`cardCount`、
  `id`（内部标识，永不外露，与 11 §7「不得用 `user.id` 冒充 covaId」同族纪律）。

## 4. 状态变体

> 通用形态引用 `17-state-gallery.md`；本屏的特殊性在于**「取不到」与「没有」必须长成同一个样子**。

- **加载**：面板展开时若 producers **尚未取到** ⇒ C–I **整块不渲染**，且**不骨架**
  （默认态就是「不可见」；任何骨架或占位都会把一个不存在的能力显成一个入口 ——
  与 08 §4「不骨架进度环」、12c §4「不骨架可能不存在的可选区」同判据，本屏推到极端：
  连容器都不显）。取到非空后**下一次展开**才出现（不在展开动画中途插内容，避免跳动）。
  ⇒ 「待裁决 1」讨论了「同一轮就出现」的另一种做法。
- **空态**：`{producers:[]}` ⇒ **没有空态**（这就是本屏的默认态）。这是本屏与其余各屏最大的不同：
  其他屏的空态是「这里应该有什么但没有」，本屏的空态是「这里本来就没有东西」。
- **错误 / 限流 / 超时 / 401**：一律**保持不可见**，不 Toast、不横幅、不「暂未开放」（A10 的
  「不是置灰」在这里推广为「不是任何痕迹」）。理由：入口的默认态就是不可见，
  错误态与默认态在观感上不可区分**是本屏想要的结果**，不是妥协。
  429（契约 §4.6 记 120/时）⇒ 同上，且**不重试**（重试会把限流窗口耗光，而拿到的东西看不见）。
- **离线**：有 owner 分桶缓存且缓存为非空 ⇒ 卡照常显示（只读展示不需要网络）+
  宿主面板的 17-S4 离线条由宿主屏承担（本屏不自建告警）；无缓存 ⇒ 不可见。
- **未登录 / 游客**：面板不可达（17-S6 拦在创作动作之前）；他端登出 ⇒ 缓存随 generation 推进
  失效（D5/D8），**不得**残留上一账号的制作人卡（灰度按账号开 ⇒ 见 §7 的 owner 分桶要求）。
- **Reduce Motion**：面板弹起退化为一帧显隐；「+N」展开退化为一帧撑开；卡片入场错峰淡入关闭。
  本屏无进度类动效。

## 5. 深浅双主题差异

- 卡底 `color.surface`（Light 浅灰 / Dark 抬升深蓝黑）、面板 `color.elevated`、
  chip 底 `color.elevated` + 描边 `color.line`、文字三级 `color.fg / secondary / muted`、
  分组标题 `color.muted`——全部为 token 双值，本屏**无专属深色底**。
- 「展开」「+N」文字钮 `color.accentText`（Light 深橙 / Dark 亮橙，手册 §3.1 双值存在的理由）。
- 本屏刻意**不使用** `gradient.ai` / `memberGold` / `enterpriseBlue`：制作人不是会员营销位
  （金色调会把它读成「付费服务」，而本屏没有任何计费事实），也不是 agent 发言。

## 6. 可访问性

- **朗读顺序**：宿主输入卡 → 「更多，按钮」（A 钮的标签；它承载的不止制作人，故不叫「制作人」）→
  面板展开后焦点入面板 →（非空时）「制作人，N 位」→ 每卡：
  「<displayName>，制作人，<tagline>，非交互内容」→「步骤，N 项」→ 每条
  「第 1 步，需求确认，先聊清楚要什么〔，展开 按钮〕」→「交付物，N 项」→ 每条
  「<条目>，标签」→「可延展，N 项」→ 每条。空/取不到时**序列里没有任何相关元素**
  （不是 hidden，是不存在）。
- **卡不可点必须被朗读出来**：`非交互内容`（避免 VoiceOver 用户找到一张卡后找不到下一步，
  而屏上又没有任何提示 —— 这是「无目标 ⇒ 不渲染钮」的必然代价，写在标签里而不是写在屏幕上）。
- `summary` 的折叠行必须带展开语义（「展开，按钮」/「收起，按钮」），不得只靠符号颜色。
- **Dynamic Type**：AX 档下面板近全屏、卡内各段上下堆叠、chip 流允许 6 行；
  「+N」钮保持单行；序号与 `label` 不同行时保持视觉配对。
- **触控目标 ≥44pt**：「+」钮 / 每个「展开」钮 / 每个「+N」/ ✕（宿主面板）。

     **证明不了**服务端真会返回这些形状（fixture 是按契约拼的，不是抓来的）。
  2. **只读生产探针**（`curl -H "Authorization: Bearer …" https://covalink.cn/api/studio/producers`）：
     记录 `200 {producers:[]}` 与响应键集 ⇒ 证明**空分支**与 A10 后半。
     **证明不了**非空分支的任何观感。
  3. **Debug-only 预览路由走查**（`SIMCTL_CHILD_COVA_PREVIEW_ROUTE=…`，§6.1 那条无需点击的腿）
     + Debug 构建注入 fixture ⇒ 出 §2 的形态截图（A14 的浅/深两张）。
     **不得进发布包**（17 §1 走查屏红线），且该截图在验收报告里必须标注
     「**形态证据（fixture），非生产数据**」——17 §9 明写示例数据不参与验收数据判定。
  ⇒ 「**待答（3）**」：请给一个已开灰度的测试账号（或把 flag 打开的测试环境），
  否则 A10 前半长期只能停在 fixture 层；这不是 iOS 侧能自证的事。
- **缓存与 owner 隔离**：`producers` 是**按账号灰度**的可见性数据（同账号稳定、跨账号可能不同）⇒
  缓存必须按 owner（principalId）分桶（D9），登出即随 generation 推进失效（D5/D8）；
  **不**进全局共享缓存池（否则 A10 的「普通账号入口不可见」会被上一个灰度账号的缓存污染）。
  新鲜度：一次冷启动取一次 + 下拉刷新（TG-09 的 5min 窗口不足以覆盖 120/时的限流窗口，
  故本屏的策略是**少取**，不是取勤）。
- **不得发明**：`ok`/`enabled`/`flag`/`gray`（无灰度位字段）、`?limit=`/`?cursor=`（列表无分页参数）、

  `producers[].price`/`credits`（**制作人若计费，本仓无一处记载** ⇒ 本屏无任何价目、无「消耗 co」字样，

- **限流面**：120/时 ⇒ 本屏的一切设计都以「取不到就当没有」为前提；不排队重试、
  不做「稍后自动再试」的定时器（看不见的能力不该占后台配额）。

## 8. 边界与文案

- **截断**：`displayName` 1 行（AX 2）；`tagline` 2 行；`summary` 收起 2 行 + 「展开」；
  chip 内单词超长 ⇒ 词内截断至 12 字 + `…`（07 §8 同档）。
- **极值**：卡数——契约未给上限 ⇒ 面板内滚动（两档吸附后仍可滚），不做「只看前 3 位」的本地裁剪
  （裁掉谁都是产品决定，不是设计能定的）；`stages` 条数无上限 ⇒ 全部列出（不折叠成「N 步」，
  折叠会让用户以为步骤少）；chips >30 个 ⇒ 前 20 + 「+N」（07 同档）。
- **并发冲突**：面板展开与 producers 请求在途 ⇒ 面板内容先按已知状态渲染，
  请求返回后**不改变已展开的面板高度**（避免键盘/滚动跳动）：非空结果在**下一次展开**生效（§4）。
  两处宿主（01 与 09）共用**同一份**缓存与同一个在途请求（不因换屏而各拉一次，120/时耗不起）。
- **零余额 / D12**：本屏**永不**出现「购买 / 充值 / 支付 / 价格 / 报价 / 下单 / 优惠 / 限时 /
  升级 / 订阅管理 / 付款 / ¥」任何字样，也**不出现**「co」——制作人与 co 币无契约关系（§7 的
  「不得发明」条目），把金调或「高级定制」类措辞放上来就是无依据的价值暗示。
- **A15 术语**：「制作人」是服务端域词（端点名 `producers`），不属 A15 的 `co / 作品 / 任务`
  三词管辖；本屏不引入「积分」「点数」等漂移词。
- **文案清单**（本屏的上屏串极少，因为**服务端字段就是内容**；每串均过禁词表）：
  `制作人` / `步骤` / `交付物` / `可延展` / `展开` / `收起` / `更多`
  - **不存在**的串（同样是规格）：`暂未开放` / `即将上线` / `敬请期待` / `功能维护中` /
    `联系制作人` —— 一句都不许出现在本屏（12d §1 的口径：那本身就是一块露出的入口）。
