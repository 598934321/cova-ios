## 3. 区块规格

- **A 导航条**：`material.navGlass`；标题「我的作品」`type.headline`；右侧「排序」文字钮
  （`type.callout` / `color.accentText`，≥44pt 热区 TG-03）→ 底部 sheet 两选一：
  「最新在前」(`sort=newest`) / 「最早在前」(`sort=oldest`)。**只有这两项**（服务端 `sort` 是二值枚举
  ⇒ 不发明「按播放次数」「按时长」）。
  - **任务定位形态**（`?job=`）：标题改「本次生成的作品」，C 筛选条与 B 搜索**整块不渲染**，
    数据源为 `GET /api/studio/create/works?id=<jobId>`（契约明写「纯 jobId 返回该 job 全部行」）；
    形态下无分页（该 job 的行恒 ≤2）。
- **B 摘要行**：`type.subhead` / `color.muted`，数字 `type.mono`。内容 = 「%d 首」，
  取响应 `total`。**`total` 的口径未文档化**（是筛选后还是全量、是否含制作中行）⇒
  本屏**照原值显示、不加「共」字、不做本地重算**，见「待答（1）」。`total` 缺失 ⇒ 整行不渲染。
  右侧搜索钮（`magnifyingglass`）→ 展开为 03 §3 同规格的搜索栏（输入即搜、300ms 防抖、
  取消钮）；搜索串进 `q`。**`q` 检索哪些列未文档化**（标题？歌词？标签？）⇒ 占位文字只说
  「搜索作品」，不说「搜歌名/歌词」（不承诺检索面），见「待答（2）」。
- **C 筛选 chips**：横滑单排，高 36（TG-07）、首尾对齐 `pageGutter`、渐隐与隐藏滚动条同 TG-34；
  选中态 `color.accentSoft` 底 + `color.accentText` 字 + 1pt `color.accent` 描边（手册 §3.6 组件态）。
  **单选**——服务端 `filter` 是单值枚举 ⇒ 不提供多选、不发明 `filter=a,b`（组合筛选走「筛选 + 搜索」叠加）。
  9 值与中文标签（标签是本屏定稿，与 A15 词表不冲突）：
  | `filter` | 标签 | 命中依据（服务端语义） |
  |---|---|---|
  | `all` | 全部 | 默认值（不传 `filter` 等价，但本屏恒显式带上，见 §7） |
  | `generating` | 制作中 | 未终态行的集合；**是否包含 `failed`/`cancelled`** 见「待答（3）」 |
  | `vocal` | 有人声 | `instrumental == false` |
  | `instrumental` | 纯音乐 | `instrumental == true`（19 已用「纯音乐」字样，同串） |
  | `liked` | 喜欢 | `favorited == true` |
  | `disliked` | 不喜欢 | `disliked == true` |
  | `cover` | 翻唱 | `operation == "cover"` |
  | `extend` | 续写 | `operation == "extend"` |
  | `remaster` | 重制 | `operation == "remaster"` |
  - 选中 `generating`/`cover`/`extend`/`remaster` 而结果为空是**正常空态**（不是错误），文案见 §8。
  - **只发这 9 个值（闭集）**：§4.7 实测「未知值服务端当 `all`」⇒ 发错值**不报错**、
    而是静默变成「没筛过」，那比报错更坏（用户以为筛过了）。chip 标签 → `filter` 是常量表，
    不做字符串拼接、不从本地化标签派生。
- **D 任务组头（本屏的合规焦点，见 §7「job 级作用域」）**

    高 = 文本 + `spacing.md`；左「%s · 一次生成 %d 首」（`type.caption` / `color.muted`，
    时间用 08 §8 相对时间口径，数量为**本页该 jobId 的行数**）；右 `⋯` 图标钮（≥44pt，TG-03）。
  - **组头 ⋯ 菜单只有 job 级三项**：`重命名本次生成的作品` / `分享本次生成的作品` /
    `删除本次生成的作品`（destructive，`color.error` 文字 + `trash`）。
    组内行数的披露写在菜单第一行的说明位：「这一组里有 %d 首，这三项操作对它们一起生效」
    （`type.caption` / `color.muted`，不可点）。**行 ⋯ 里永不出现这三项** —— 作用域靠
    「物理上放不到一行上」来表达，比贴一句警告更可靠。

  - **跨页切断**：同一 jobId 的两行若被 cursor 分页切开，第二页首行前**重新出现同一组头**

  - 主标题后追加**状态徽标**（`../17-state-gallery.md` 无此项，取组件 §9 语义的胶囊：
    `type.caption`、`radius.capsule`、底 `color.surface`）：文案**一律取
    `GenerationJobStatus` 的中文标签**（A15 术语唯一源，与 19 §3.D 同源）；屏上不得出现
    `queued/processing/succeeded` 等英文态名（17 §10 禁令）。

  - 副标题 = 时长（`type.mono`）+ `instrumental == true` 时「纯音乐」徽标（同 19）。

## 4. 状态变体

> 通用形态（17-S1 骨架 / 17-S2 空态 / 17-S3 四形态与判定表 / 17-S4 离线 / 17-S5 Reduce Motion /
> 17-S6 游客引导 / 17-S7 Dialog）唯一源为 `17-state-gallery.md`；本节只列本屏实例。

- **加载（首载）**：B 一条骨架；C chips **不骨架**（它们是本地常量的 9 枚标签）；
  E 六行骨架（48 方快 + 两条文本条 + 右端两枚短条），`color.surface` 呼吸；D 组头不骨架
  （组是聚合出来的形状，骨架会教用户错的结构）。
- **加载（分页）**：底部追加 3 行骨架，不盖住已有行；失败 → ① Toast「这一页没取到」+ 行内「重试」文字钮。
- **空态**（三种，措辞各自独立，都走 17-S2 三段但**不带**「清除筛选」以外的第二 CTA）：
  1. `filter=all` 且无行 → 插画位 + 「还没有你的作品」+ 「一句话就能做一首：说场景、说情绪、说人声」+
     主 CTA「做一首歌」→ 19（与 08/12c 的「开始新会话」区分：本屏的产物是**作品**，不是会话）
  2. 带筛选/搜索无结果 → 无插画位（17-S2 变体：03 无结果同规则）+ 「这个筛选下没有作品」+
     次按钮样式「清除筛选」；**不**显示「试试别的关键词」两句叠加
  3. `filter=generating` 且确无在制任务 → 「没有在做的了」（正常结果，不是空态插画）
- **错误**：首载失败无缓存 → 整屏 ④「作品列表没取到」+「重试」；有缓存 → 保留内容 + 17-S4 细条；
  动作失败（♡ / 不喜欢 / 做成笔记 / 重命名 / 删除 / 分享）→ ② **行内或组头回落原态** + 一次 Toast
  （文案 §8）；401/403 → 17-S6；429 → 服务端 `error` 原文，**不做倒计时**（本仓 `HTTPResponse`
  无 header 面，19 §4 同判据）。
- **离线**：有缓存 → 列表照常 + 17-S4 横幅「离线，展示上次内容」，全部写动作不渲染
  （不是置灰：手册 §3.6 disabled 规则 + 17-S4「必须禁用任何写操作」）；无缓存 → 整屏
  「离线：作品需要联网」。本机已存的作品行 ▶/↓ 仍可用（`file://`，不发网络，同 19 §4）。
- **未登录 / 游客**：不可达（§1）；他端登出 → 回落 17-S6 且缓存随 generation 推进失效（D5/D8/D9）。
- **Reduce Motion**：命中 `17-state-gallery.md` §S5 的行有 —— push/present 一帧到位、行入场错峰淡入关闭、

## 6. 可访问性

- **朗读顺序**：「我的作品，标题」→ 返回 → 「排序，最新在前，按钮」→ B 摘要（「12 首」）→
  （搜索展开时）「搜索作品，编辑栏」→ C「筛选，横向滚动，9 项，已选中 全部」→ 每枚 chip
  「喜欢，筛选，按钮 / 已选中」→ 每个任务组：先组头
  「两小时前的那次生成，这一组里有 2 首，更多操作，按钮」→ 组内每行
  「<标题>，2 分 38 秒，播放 按钮，保存到本机 按钮，喜欢 按钮 已选中，更多操作 按钮」→
  （失败行）「这次没做成，可以再试一次」→（占位行）「这首还在做」→ F 尾部行。
- **job 级作用的朗读必须带范围**：组级钮一律念「重命名本次生成的作品，按钮」，
  **不得**简写为「重命名」；行级 ⋯ 里没有这三项（§3.D），所以用户不可能在只作用一行的位置听到全局措辞。
- 状态徽标不独立成元素（值并入行标签首段）；`errorMessage` 作为行标签的一部分朗读（不能被颜色单独表达）。
- **Dynamic Type**：AX 档下——E 行标题 1 行 → 2 行、时长与徽标换到第三行、行高自适应；
  四枚行内钮在一行放不下时**整排换到第二行**（不缩热区）；C chips 保持单行横滑（不换行，
  横滑即可）；D 组头两行堆叠；B 摘要与搜索钮同行保留。
- **触控目标 ≥44pt**：返回 / 排序 / 搜索钮 / 每枚 chip / 整行 / ▶ / ↓ / ♡ / 行 ⋯ / 组 ⋯ /
  sheet 每行 / Dialog 两钮 / 空态 CTA / 重试钮 / 「清除筛选」。

| 用途 | 端点 | 字段与说明 |

| 播放 / 直存 / 上报 | `audioUrl`；`POST /api/tracks/play` | 与 19 §7 同源：播只吃 `audioUrl`（`playbackUrl` 落在名单外的桶，手册 §7 #37 / D23 不改）；**手册 §7 #39 已于同日推翻旧结论**——同源 `/api/media/objects/` 把独立成项的 `intent=play` 换成 `intent=download` 即 **200 直出字节、零跳转**（客户端已修 `CovaEnvironment.workAudioDirectFetchURL`，**D23 名单一个字都没放宽**）⇒ 本屏的 ▶/↓ **今天可落盘**；起播上报 `trackId = "{jobId}:{candidateId}"`、`source = player`（手册 §5 P1-3 记的两处偏差按实测保留） |

- **分页（游标形态，本屏最容易做错的一条）**：`cursor` 是**字符串化的行偏移**——
  §4.7 明写「服务端 v1 简化，**不是不透明游标**」，实测 `limit=6` 回 `nextCursor="6"`。
  本条同时纠正本规格早先的「不透明」假设，但**施工纪律一条不减**：
  ⇒ ① 客户端**仍然不自己算、不自己 +1**：参数名承诺的是游标，实现不该去赌它下一版还是行偏移；
  且 `offset`/`page` 作为参数**根本不存在**（§4.7 逐条实测过）；
  ② 只回传上一次响应里的 `nextCursor`；`nextCursor` 为空即到底；
  ③ `limit` 固定 `30`（本轮口径给定的默认值，上限 100 ⇒ 本屏不写大数：列表行高 64，
  一屏 30 行已足够翻页手感，取 100 只是把首屏解码成本推给冷启动）；
  ④ 任何 `filter` / `q` / `sort` 变更 ⇒ **cursor 归零**、列表整体替换（不保留上一页尾巴，
  跨筛选复用 cursor 会拿到错页 —— 它语义上行偏移，不携带筛选身份）。
  ⑤ **漂移是机制、不是意外**：既然是行偏移，翻页期间新增/删除一行就会让下一页整体错位
  （重复一行或漏一行）。客户端的承接只有两条：按 `id` **去重**（同 id 只保留首次出现的行）、
  **不**因此重排。§4.7 没有幂等游标可用 ⇒ 「待答（4）」收窄为一句：
  v1 的行偏移何时换成不透明游标或按 job 边界对齐。
- **job 级作用域（本屏的两条硬事实之一，必须显式处理）**：`重命名 / 删除 / 分享` 是
  **任务级**，而一次生成会产生 **2 行** ⇒ 作用在一枚卡上等于作用在两枚卡上。
  ① **请求侧**：客户端一律用**该行自己的 `id`**（`{jobId}:{candidateId}`）发请求 ——
  作用域由服务端从 `id` 里解出 `jobId` 决定，**不是**客户端「换个更合适的 id」能控制的；
  ② **UI 侧**：三重披露 —— 几何分组（D 组头把两行归一件事）、位置隔离（job 级动作只存在于组头 ⋯，
  行 ⋯ 里没有）、措辞复述（「这一组里有 %d 首，这三项操作对它们一起生效」+ VoiceOver 全称）。
  ③ **状态回显**：分享态（`已分享` 徽标）由组头承载，组内所有行同时呈现同一状态；
  删除成功后本地移除**该 jobId 的全部行**（含跨页已取到的）；
  ④ **回填**：`PATCH` 响应是单数 `work` ⇒ 不能只补一行。重命名成功后用
  `?id=<jobId>` 回读该 job 全部行覆盖本地（契约明写该形态，不发明 `?ids=`）。
  ⑤ **口径来源**：§4.7 已就地记录这三项为 job 级（原文：「`rename`/`delete`/`share` 是 job 级
  不是行级（一次生成两行 ⇒ 改一行等于改两行），**屏上怎么交代归规格**」——上面 ② 就是那份交代）；
  并证实「七个端点**都接受伪 id**」⇒ ① 的「一律用行自己的 `id`」可行。
  仍欠一处：`DEVELOPMENT.md` §4.4 的行内动作表没有作用域列，第二端只读 §4.4 会按行级理解
  ⇒ 「**待答（5）**」降级为「请把 §4.7 的作用域结论同步进 §4.4 的表」。
- **分享钮的可见性（两条事实之二）**：手册 §7 #24 现行口径 ——
  「生成候选无公开分享目标；**现状：不渲染分享钮；`works/:id/share` 只解 create 作品**」
  ⇒ 本屏规则：**无目标 ⇒ 不渲染分享钮**（不是置灰、不是点了再报错）。判定按 `source`：
  `source == "studio-create"` ⇒ 组头 ⋯ 出现「分享本次生成的作品」；
  `source ∈ {one-step, song-match}` ⇒ 该项**不渲染**。
  本屏**只有这一个判别式可用**（`CreateWorkItem` 无 `shareable` 布尔位）⇒ 登记
  「**待答（6）**：`works/:id/share` 对 `one-step` / `song-match` 来源是否真的 404/409？
  若可用，请在响应里给 `shareable`；不可用则明确一句，客户端按 source 分型永久承接」。
- **♡ 的两条写通道必须收敛**：`source == "one-step"` 的行同时有 09 的候选收藏通道
  （`PATCH /api/media/references/:id/retention`）。本屏统一走 `works/:id/favorite`，
  但两处状态必须互为回填（否则「会话里点了心、作品列表里没心」）。登记
  「**待答（7）**：两条通道写的是不是同一个布尔？请给单一事实源，或让 retention 与 works/favorite 互相同步」。
- **动作端点的三条实测细则（§4.7，全部直接影响 UI）**：
  ① **缺键 ≠ false**：`favorite` / `dislike` 的 body 里服务端把「没带键」读成 `true`
  ⇒ **取消收藏必须显式发 `false`**（不发送取消，会反过来点亮）。UI 面：♡ 的两态切换
  一定要把布尔值带上，不许用「不带键 = 默认动作」的省事写法。
  ② 错误形如 `{error:字符串}`（单个字符串，无 `code`），**409 = 作品尚未生成完成**
  ⇒ 占位行（`pending-N`）本就不渲染任何动作（§3.E），所以 409 正常路径上不该出现；
  真出现了按「这首还没好」行内一句（§8），不弹 Dialog。
  ③ `favorited` / `disliked` **为 false 时服务端整个键都不发** ⇒ 「缺键 = false」是
  **服务端行为**，与本仓「字段缺失即不建模、不填默认值」的通则在这一处**由契约让位**：
  ♡ 的渲染按 `favorited ?? false` 判定，但**解码层不得把这个兜底写进 DTO 存储**
  （DTO 仍可选、判定发生在渲染层），否则下次就分不清「服务端没发」与「服务端发了 false」。
- **`POST works/:id/note` 的语义边界**：它是**物化成笔记**（work→`music_note`，回 `{ok,noteId}`，
  进歌单用），**不是**「给这首写句备注」。⇒ ① 菜单标签写「做成笔记」，**不写**「备注」；
  ② 本屏**不**提供备注文本编辑 —— 文本属 note 对象，走 `PATCH /api/notes/{id}`（§4.7 已确认
  这条腿存在），但**仍未进 §4.2 的端点表**（那里只有 `POST/DELETE /api/notes/:id/favorite`），
  并且带出一条新风险：**`storyText` 同时是物化关联键 ⇒ 改它会断开收藏回读**（§4.7）。
  这一条把「不接备注文本」的理由从「没契约」升级为「**有契约，但改它会破坏另一条读路径**」。
  ⇒ 「待答（8）」。
  ③ 物化成功后**不承诺**「去收藏/歌单里能看到它」：`GET /api/favorites` 的 note 条目属手册 §7 #11
  未解锁项，12a 现行为「静默跳过不可解码条目」⇒ 本屏 Toast 只说事实「已做成笔记」。
- **`timing` 与 D15 的关系（本屏的第二处「不许顺手多做」）**：`GET works/:id/timing` 确实回 LRC，
  但 `17-state-gallery.md` §10 把「逐行时间轴歌词」列入**禁止承诺**（D15）。本规格的裁决：
  取到 `lrc != null` ⇒ 歌词 sheet（§3.G）按**静态行文 + 时间戳前缀**呈现，
  **不做与播放进度联动的逐行高亮/自动滚动**（那需要播放器与歌词层同车，属另一批活，见「待裁决 3」）；
  `lrc == null` ⇒ 回落 `CreateWorkItem.lyrics` 纯文本；两者都空 ⇒ 「这首还没有歌词」，
  纯音乐行本就无「歌词」项（§3.E）。
- **字段可空规则**（缺失即不渲染、不填默认值，附录「新增端点 → 先建 DTO」纪律；
  **唯一例外**是 `favorited`/`disliked` 的「缺键即 false」——那是 §4.7 明写的服务端行为，
  见上面「动作端点的三条实测细则」第 ③ 条）：
  `title` 空 → 「未命名作品」（19 同串）；`duration` null → 时长位不渲染（**不显 `--`**：
  11 §7 的 `--` 是「数值未同步」，这里本就没有数值）；`coverUrl` null → `color.surface` 底 + 音符占位；
  `jobId` 缺失且 `id` 无 `:` ⇒ 该行**不可作为组头锚点**，单行成组（组头仍渲染，时间用
  `createdAt`，缺则组头只写「一次生成 1 首」）；`createdAt` 空 → 组头时间位不渲染；
  `operation` 缺失 ⇒ 不渲染任何模式徽标（不猜「create」）；`tags` 空 → 行内不出标签胶囊
  （12a/12c 同判据：资产列表页焦点是清单，不是标签）。
- **刷新与缓存**：`no-store` ⇒ 服务端不鼓励缓存，但本屏**允许**短时本地快照用于离线与二次进入
  （按 owner 分桶，D9；只存展示字段与**本地文件名**，`audioUrl`/`playbackUrl` 一律不落盘、
  不入日志，硬边界 3 / TD-23）；进入本屏不自动重取（≤5min，TG-09）；下拉刷新 = 从第一页重取并**整表替换**；
  行内动作成功后就地回显该字段，不整表重取。轮询在本屏**不存在**：`generating` 行不自动变
  （用户下拉才更新）—— 本屏不是任务等待屏，等待发生在 19（同 12c §7「避免两处并发轮询」的口径）。
- **不得发明的字段/端点**（本屏是「顺手补一个」高发区，明令列出）：
  `shareable`、`noteId`（GET 侧不回）、`savedAt`、`playCount`、`favoriteCount`、
  `?limit=100` 之外的 `?offset=`、`?filters[]=`、`?sort=popular`、`GET works/:id`（单行详情）、
  「批量删除」端点、`PATCH /api/notes/:id`（未进契约前不调）——
  全部按「无 ⇒ 不做、不渲染、不写文案」处理。

## 8. 边界与文案

- **截断**：作品标题 1 行（AX 2 行）；组头一行；`errorMessage` ≤3 行后中段截断；
  重命名输入框内不换行（提交后按标题规则截断）。
- **极值**：`title` 200 字（服务端上限）⇒ 本地 1–200 判定，超出即输入端截断，
  **不发出去换 400**；`q` 无文档化上限 ⇒ 本地钳到 200 字（同 `title`，见「待答（9）」）；
  单页 30 行、连续翻页 ≤10 页后停止自动加载并要求用户下拉（防 offset 漂移放大）；
  一次生成恒 ≤2 行。
- **并发冲突**：
  - 同一行的 ♡ 与 ⋯「不喜欢」互斥 ⇒ 客户端在途只允许一个写（后到者被吞，17 §10 并发通则）；
    服务端为事实源，失败即回落。
  - 组头 ⋯ 与组内行 ⋯ 不同时开（互斥的两条菜单，开一个即关另一个）。
  - 重命名/删除 sheet 或 Dialog 打开期间收到下拉刷新 ⇒ 丢弃刷新结果（不覆盖正在编辑的行的本地态），
    动作成功后再取。
  - 两设备同账号：他端删了一整组 ⇒ 本端点该行得 404/410 —— **未文档化** ⇒ 按「这行没取到」行内回落 +
    静默移除（不弹「已被删除」的断言，因为我们不知道是谁删的，见「待答（10）」）。
  - 本屏与 19 结果区共读同一 job 的行：19 提交成功后返回本屏 ⇒ 首屏整表重取（不本地插行），
    因为 `no-store` 且服务端 `createdAt` 排序才是事实源。
- **零余额 / D12（硬边界 9）**：本屏**永不**出现「购买 / 充值 / 支付 / 价格 / 报价 / 升级 /
  订阅管理 / 付款 / 下单 / 优惠 / 限时 / ¥」任何字样；余额不在本屏出现（属 11 与 22）；
  「保存到本机」是本机直存、**不扣费**，措辞不写「下载（需 co）」那类暗示（BUG-15 双路径分野，
  见 21 §1 的对照表）；分享出去的地址是**公开链接**（免登录可听），与签名 URL 不同族 ——
  `sharePath` 可显示可复制，`audioUrl`/`playbackUrl` 永不显示。
