# 12a · 我的收藏（曲目）

> G2 逐屏规格。基准 393×852pt。要点源：`inventory.md` 行 12（四屏同构，本文件为**同构基线**，
> 12b/12c/12d 引用本文件的骨架并只写差异；共享状态规范源：`17-state-gallery.md`）。
> 数据源：`GET /api/favorites`（api-contracts §2）。

## 1. 屏与上下文

- **层级**：push 自主内容屏；入导航栈（`inventory.md` 行 12 的「列表页」形态，非 modal）。
- **入口**：① 11 我的 →「我的资产 → 收藏」（04 §5：原抽屉项并入此行）；② 深链 `favorites`。
- **互链**：行 → 播放（02 + MiniPlayer）/ ♡ 取消收藏 / ⋯ → 07 曲目详情 / 16 音乐人；
  空态 CTA → 05 歌单广场 或 03 曲库。
- **返回**：退栈回 11（页签栈规则见 04 §2/§3）。
- **登录门槛**：需登录（写与读均需 Bearer）。游客从 11 进入 → 17-S6 引导。

## 3. 区块规格（骨架各块）

- **A 导航条**：`material.navGlass`；标题 `type.headline`（push 屏，用 headline 而非 05/08 的
  `type.title`，因为标题更长：「我的收藏」）；右侧「编辑」文字钮（`type.callout` / `color.accentText`，
  ≥44pt 热区 TG-03）→ 多选态（§4）。空态时右侧动作**不渲染**
- **B 摘要行**：`type.subhead` / `color.muted`，`type.mono` 数字；左右 `spacing.pageGutter`，
  下间距 `spacing.md`。内容 = 「N 首 · 约 H 小时 M 分」（不足 1 小时改「约 M 分钟」）。
  求和源为 `tracks[].duration` 累加（**客户端计算**，契约无汇总字段）
- **C 列表主体**：`../components.md` §1 TrackRow 原样（高 64、封面 48、圆角 8 → 见 §Token 缺口
  TG-31），左右 `spacing.pageGutter`；行间分隔 `color.lineSubtle` 1pt（TG-04），首行不加；
  本屏行内**不显示标签胶囊**（与 03 区分，收藏页焦点是「我的清单」）
- **D 尾部状态行**：`type.subhead` / `color.muted`，上下 `spacing.xl`，文案 §8
- **E 左滑动作**：单枚 destructive（`color.error` 底 + 白 `heart.slash` 图标 + 「取消收藏」），
  几何同 08 §3.E（TG-20）
- **多选态（编辑）**：行左侧出现勾选圈（22pt 档 TG-18，未选 `color.line` 描边 / 已选
  `color.accent` 填充 + 白勾），导航条右侧替换为「全选 / 完成」，底部出现操作条
  （`color.elevated` + 1pt `color.line` 上边，高 = 主钮 50 + 上下 `spacing.md`）内一枚
  destructive 文字钮「取消收藏（n）」

## 4. 状态变体

> 通用态样式（骨架呼吸 17-S1、空态三段 17-S2、Toast/行内/区块内/整屏四形态与判定表 17-S3、
> 离线 17-S4、Reduce Motion 17-S5、游客引导 17-S6、Dialog 17-S7、四屏同构骨架 17-S9）
> 唯一源为 `17-state-gallery.md`；本文件 §2–§6 是 12 系列骨架基线；此处只列本屏实例。

- **加载**：8 行 TrackRow 骨架（48 方快 + 两条文本条 + 右端短条）；B 摘要行骨架一条；
  A「编辑」不渲染（无内容时不可编辑）
- **空态**：插画位 + 「还没有收藏」(`type.headline`/`color.fg`) +
  「听到喜欢的歌点一下 ♡，就会出现在这里」(`type.callout`/`color.secondary`) +
  两枚 CTA：主「去曲库挑歌」→ 03、次（文字钮）「先看看歌单」→ 05
- **错误**：首载失败 → 整屏（无内容可留）；刷新失败 → Toast；取消收藏失败 → **行内**
  （行回落原态 + Toast「取消收藏没保存上，再试一次」）；批量提交部分失败 → Toast
  「N 首没取消成功，已保留在列表」并把失败行勾选中保持勾选态
- **离线**：有缓存列表 → 正常显示 + 17-S4 离线条；取消收藏**排队**（乐观 + 待重放，与 06 待裁决 2
  同一条裁决口径）；无缓存 → 整屏「离线：收藏需要联网」
- **未登录 / 游客**：不可达（§1）；进入期间他端登出 → 回落 17-S6 引导 sheet
- **Reduce Motion**：入场错峰淡入关闭；左滑弹回一帧到位；勾选态颜色切换无缩放动画；
  骨架呼吸 → 静止色块（17-S1）

## 5. 深浅双主题差异

- 底 `color.canvas`、行文本三级 `color.fg / secondary / muted`、分隔 `color.lineSubtle`、
  骨架 `color.surface`、多选操作条 `color.elevated` —— 全为 token 双值，本屏无专属差异
- Dark 下 destructive 滑出层与 `color.error` 同值；勾选圈描边 `color.line`
- 无渐变、无玻璃（除 A 导航条与 MiniPlayer），因此两主题观感差异最小的一屏

## 6. 可访问性

- **朗读顺序**：「我的收藏，标题」→ 返回 →（有内容时）编辑 → B 摘要（「36 首，约 2 小时 14 分」）→
  「收藏列表，36 项」→ 每行：第一元素「<曲名>，<艺人>，<时长>，按钮」、第二元素「取消收藏，按钮」、
  第三元素「更多，按钮」→ D 尾部行
- 播放中行的音量 symbol **不**播报（装饰），改为行标签前置「正在播放，」
- **Dynamic Type**：AX 档下 B 摘要允许 2 行；TrackRow 两行文本各自允许 2 行 → 行高自适应
  （封面 48 不缩，行最小高由内容撑开）；多选态底部操作条文字钮全宽
- **触控目标 ≥44pt**：编辑 / 返回 / 整行 / ♡ / ⋯ / 左滑动作 / 每个勾选圈 / 全选 / 完成 /
  批量取消收藏钮 / 空态两枚 CTA / 重试钮

## 7. 数据契约

| 用途 | 端点 | 字段 |
|---|---|---|
| 列表 | `GET /api/favorites` → `{tracks[]}` | `TrackDto` 普通列表投影：`id/title/titleCn/cover/duration/artist{…}/audioUrl/…` |
| 单条取消 | `DELETE /api/favorites`，body `{trackId}` → `{message, favoriteCount}` | 用 `favoriteCount` 回填条数（B 摘要可直接采信，替代本地重算） |
| 单条新增 | `POST /api/favorites`，body `{trackId}` → 同上 | 由 02/03/06/07 发起，本屏只读结果 |
| 批量取消 | **v1.0 逐条 `DELETE` 并发 + 幂等键** | 契约无批量端点（api-contracts §2 只有单条 `{trackId}`）→ **不得**发明 `POST /api/favorites/batch`；见「待裁决 1」 |

- **NEEDS-11 未解锁**（`GET /api/favorites` 的 `{tracks}` 混入「生成音乐收藏」条目，带
  `source:"note"` / `noteId`，字段集不同）→ UI 降级（硬性）：
  1. 解码按条目判别：**只渲染可解码为 `TrackDto` 的条目**；
  2. 未识别条目**静默跳过**——不渲染占位行、不显示「暂不支持的内容」噪声行；
  3. B 摘要条数 = **已渲染条目数**（若后端 `favoriteCount` 与本地渲染数不一致，
     以本地渲染数为准，`favoriteCount` 仅作校验信号，不显示）；
  4. 被跳过的生成物收藏在 09 的候选卡 ♡ 态与 12c 的会话里仍可寻回（不宣称丢失）；
  5. **不得**为凑齐条数而显示「+N」类补数文案（用户会去找不存在的东西）。
  解锁后端后本条降级回收，登记以便回撤。
- **排序与分页**：响应无 `savedAt`、无分页参数（api-contracts §2）→
  ① **以后端返回顺序为准，客户端不重排**（重排会制造「我明明刚收藏的不在最前」的误解，
  而后端口径未文档化）；② 无「按收藏时间排序」选项（无字段支撑）；③ 全量渲染 + 到底显
  「已显示全部」；下拉刷新重取
- **可空/异常字段规则**：`titleCn` 空 → `title`；`cover` 空 → 占位（`color.surface` + 音符）；
  `duration` 为 0/空 → 该行时长位显 `--`（**保留行**，不可因缺时长丢条目），B 摘要求和时跳过该条；
  `artist` 缺 → 第二行显「未知艺人」（`color.muted`）；`audioUrl` 空 → 行仍显示、点击播放时
  由播放层给 Toast「这首暂时不能播」

## 8. 边界与文案

- **截断**：曲名/艺人名按 components §1 两行（中文优先），时长 `type.mono`
- **零结果**：见 §4 空态；筛选/搜索在本屏 v1.0 不提供（无契约支撑）
- **极值**：>1000 首 → 分帧渲染 + 滚动 60fps（PRD §5）；全选 1000 条 → 逐条 DELETE 需
  限并发（建议 ≤4 并发，客户端策略值 TG-32），且操作条文案「取消收藏（1000）」不换行
- **并发冲突**：
  - 左滑取消与多选取消同一行同时发生 → 以先发起者为准，后者吞掉（行只消失一次）
  - 在 02 播放器里点 ♡ 取消收藏 → 本屏若在前台栈中，行**即时移除**（共享本地态），
    不依赖下拉刷新；后台栈中则进入时静默刷新
  - 播放队列里存在被取消收藏的曲目 → 队列不因此改动（取消收藏 ≠ 移出队列），
    如用户想移出走 02 §6 队列面板
- **零余额 / D12**：本屏无下载/购买入口；TrackRow 的 ⋯ 菜单里「下载」项在放行前不渲染
  （与 07 §3.F 同一条 D12 规则）
- **文案清单**：`我的收藏` / `编辑` / `全选` / `完成` / `取消收藏` / `取消收藏（%d）` /
  `还没有收藏` / `听到喜欢的歌点一下 ♡，就会出现在这里` / `去曲库挑歌` / `先看看歌单` /
  `已显示全部` / `加载中…` / `取消收藏没保存上，再试一次` / `%d 首没取消成功，已保留在列表` /
  `离线：收藏需要联网` / `未知艺人` / `这首暂时不能播`

## 待裁决

1. **批量取消收藏**：契约无批量端点。本规格 = 逐条 DELETE（限流）。若产品要求原子批量，
   需后端补端点（NEEDS 候选 `FAVORITES-BATCH`）。
2. **收藏时间排序 / 分组**：无 `savedAt` 字段 → v1.0 不排序。若需「按收藏时间」，
   后端须在 `{tracks}` 元素上带排序键（NEEDS 候选）。
3. **离线写是否排队**：与 06 待裁决 2 同一口径，需一次性裁决（收藏/歌单收藏/队列移除三类本地写）。
4. **多选态是否支持「加入歌单」**：v1.0 无个人歌单创建/加入端点（api-contracts §2 只有
   saved-playlists 收藏官方歌单）→ 不做。若产品要，属新契约需求。
