**为什么这么切**：18 的全部风险都在"什么时候发 / 发什么 / 载荷里不能有什么"，
这三件事都不需要系统框架 ⇒ 放进 `CovaCore/StudioNotificationPlan.swift` 的**纯规划器**，

**规划器钉住的规则**（每条都有用例，实测 7/7 绿）：
· 双 Demo 硬规则（D7）：只看**前两个**候选，两个都 settled（就绪或有失败记录）才算终态；
  `succeeded` 但没都 settled ⇒ **不发**；不足两个候选 ⇒ 不发；第三个候选就绪与否**不改变判定**；
· 两个都失败 ⇒ **照发**（spec 明令），且正文不带 ❌ / ！这类情绪符号；
· 载荷卫生：标题/正文/userInfo 里不得出现 `http`、签名地址、`SECRET`、`co 币`、`余额`、
  `价格`、`costCredits` 的数字（夹具故意塞了 `costCredits: 30` 与带 `?sig=SECRET` 的 URL）、
  「点击查看/领取」诱导词；
· 路由契约：`sessionId` 缺失或全空白 ⇒ 计划里不给会话号，`route(from:)` 返回 `nil`
  ⇒ UI 回落首页，**不猜路由**；
· 一个 job 只登记一次：标识 `cova-generation-<jobId>`（同轮多 job 由调用方合并）。

**系统侧薄壳的三条时机**：只在 09「开始制作」成功之后索权（`.denied` 之后不再索、也不自建开关）；
前台收到 ⇒ `willPresent` 返回 `[]` 不展示并撤掉那条待发；登出 ⇒ `removeAllPending…` +
`removeAllDelivered…` + 角标归零 + 清自记清单。
兜底通知的正文「两个版本应该好了，去 Cova 听」是 spec 标了**待裁决 1** 的措辞 ⇒ 代码里就写明
"待用户裁决"，不在裁决前悄悄换成自己的话术。

**踩到的三个真坑（都写进注释，免得下一个人再踩）**：
1. `removePendingNotificationRequests()` 不存在 —— 全部撤销的 API 叫 `removeAll…`，
   带 identifiers 的才是 `remove…(withIdentifiers:)`；
2. `UNUserNotificationCenterDelegate` 的 conformance 不能整类钉在 `@MainActor` 上
   （系统在其自有队列回调 ⇒ Swift 6 判跨隔离），要跳主 actor 的地方显式 `Task { @MainActor in }`；
3. 点按载荷 `[AnyHashable: Any]` 不是 Sendable，直接送进 `Task` 被判数据竞争 ⇒
   先收成 `[String: String]` 再跨隔离。

**没做的（据实）**：深链载体 `cova://` 需要往 `Info.plist` 加 `CFBundleURLTypes`，
而 18 的载体本身**尚未裁决**（spec 给了两个候选）⇒ 不动 plist（那是需要用户批准的动作），
现在只走 App 内 `userInfo` 路由；真机通知投递（TD-42/44 同一类）没有设备可验。
