## 二、最小机制

1. **决策与 I/O 分离**：`PlaybackCoordinator`（actor）+ `PlayQueue`（纯索引数学）+
   `SeekArithmetic`（纯算术）+ `AudioSessionReducer`/`AudioSessionNormalizer`（纯函数）+
   `PlayReportCoordinator`（幂等账本）+ `NowPlayingCommandRouter`/`NowPlayingStatusMapping`（纯映射）
   —— 全部不 import AVFoundation/MediaPlayer，因此可零硬件、零网络、确定性断言。
2. **系统面只做搬运**：`AVPlayerEngine` / `AVAudioSessionAdapter` / `MPNowPlayingController` /
   `URLSessionPrivateAudioTransport` 是薄适配器；每个适配器都留一组 `static` 纯映射
   （`playableURL` / `seconds` / `time` / `event(for:)` / `payload(from:)` / `interruptionKind` /
   `routeChangeReasonKind` / `remoteCommand` / `handlerStatus` / `infoDictionary`），
   使「系统类型 → 内部词汇」的映射本身可测，而真正的系统调用只留最少行数。
3. **注入式时间与信号**：`CovaClock`（虚拟时钟）驱动 Now Playing 节流；测试等待一律用
   `SignalCounter` + `Signals.wait`（有真实时间上界，超时把挂死转成变红），不做让步计数（D16⑤）。
4. **D7 写进类型**：`PlaybackItem.AudioSource` 三态（publicDirect / bearerRequired / localized）+
   `playableURL == nil`（需 Bearer 时）+ `PlaybackSourcePreparing` 关口 + `AVPlayerEngine.load`
   的第二次拒绝 —— 绕过本地化没有代码路径。
5. **D8 写进会话值**：`PlaybackSessionContext(owner, generation)` 贯穿协调器、上报器与取回器；
   登出/换号 → 丢未决上报 + 停播放 + `purge` 该 owner 的私有音频。

## 三、假设清单（逐条对证，全部实测）

| # | 假设 | 对证 |
|---|---|---|
| A1 | 「`PlayQueue.step` 可以在查询时顺便改索引」 | **不采用**。查询与提交分离（`step` 纯查询 + `apply` 唯一写入点），否则测试里重复断言会污染队列、裁决表无法逐条固定。 |
| A2 | 「`.one` 只在末项播完时重复当前项」 | **假**。`.one` 的 itemEnd **优先于**「后面还有曲目」：任意位置播完都回到当前项 0 位置（design §5 单曲循环）。 |
| A3 | 「失败时可以 `.repeated` 重试当前项」 | **假**。`itemFailed` 在 `.one` 下也必须离开当前项，否则对同一坏源无限重试（`.one` 失败按回绕前进处理）。 |
| A4 | 「duration 未知时 ±15s 也该钳上界」 | **假**。无上界信息时钳上界 = 伪造边界；只钳下界 0，后到 `duration` 事件时纠正，纠正后恰落末端按「播完」继续。 |
| A5 | 「`ended` 事件只会来一次」 | **假**。`AVPlayerItem.didPlayToEndTimeNotification` 与 boundary/KVO 可双发 → 仅 `.playing/.buffering` 状态接受 ended，其余 `.held`（重复上报忽略）。 |
| A6 | 「连续 3 次失败 = 第 4 次才停」 | **假**。第 3 次即终态（`limit = 3`，`failureStreak` 到 3 时停止自动推进）；取消类失败不计数。 |
| A7 | 「`AVAudioSession.InterruptionType.ended.rawValue == 2`（或 1）」 | **假**。iOS 26 SDK 实测 `began.rawValue == 1`、**`ended.rawValue == 0`**。按「1/2」口径写死 → `InterruptionType(rawValue: 0)` 被认成 ended 的**反向**问题：把 ended 写成 2 会映射成 nil → 中断结束永远不进决策 → 来电后不续播，且**没有任何崩溃或日志**。这是本轮修掉的主缺陷。 |
| A8 | 「`RouteChangeReason` 的 3 是拔耳机」 | **假**。3 = `categoryChange`；`oldDeviceUnavailable` 与 `newDeviceAvailable` 是相邻另两个值。原测试里 `routeChangeReasonRaw: 3` 配「暂停」的期望恰好靠探针成立 → 数值语义完全错位。改为以 SDK 常量为键映射。 |
| A9 | 「`InterruptionOptions` 有 `.none` 可以构造负例」 | **假**（无该成员）。且它是 OptionSet：任意「越界整数」如 9_999 **末位为 1，恰好命中 `shouldResume`** → 拿字面量当负例会把缺陷藏进测试。负例改为 `shouldResume.subtracting(.shouldResume).rawValue`。 |
| A10 | 「`CMTime(seconds: .nan, preferredTimescale:)` 会让 `CMTimeGetSeconds` 返回 NaN」 | **假**。实测归一为 value 0 → 返回 0.0；真正的 NaN 来源是 `.invalid`/`.indefinite`（timescale 0）。`seconds(_:)` 的 `isFinite` 守卫覆盖后者，前者按 0 处理是正确行为。 |
| A11 | 「Xcode 不为本地 SwiftPM 包目标产出 xccov 逐文件行数」（TD-2/TD-5/TD-7 的既有口径） | **在 iOS destination + `-enableCodeCoverage YES` 下为假**：实测 `xccov view --report` 列出 15 个 `Packages/CovaPlayer/Sources/**.swift` 的真实行数，target 行 = 各文件行之和（2400）。故 TD-1 用 xccov 直接闭环，不需要 profdata+llvm-cov 回退路径（该路径保留为 §六 的备选记录）。 |
| A12 | 「凭证快照的 generation 与请求 session 的 generation 可以不同」 | **假**（会被 `sessionBinding` 判为 `.staleSession` 而根本不写文件）。测试要为「新代次的文件」准备推进过快照的提供者，否则用例变成空转通过。 |
| A13 | 「teardown 之后 start/resume 会自然失效，因为队列已清」 | **部分假**：`resume()` 确实因空队列早退，但 `start(items:)` 会重新装载并进入 `.playing`，而 `attach()` 因 `tornDown` 不再接事件流 → 「在出声却没有事件归约」的半死状态。已加守卫（`.rejected(.tornDown)`）。 |
| A14 | 「`String(describing: PlaybackItem)` 会带出签名 query」 | **假**。`AudioURL` 的 `CustomStringConvertible` + `CustomReflectable` 双写使反射面只剩 `scheme://host/<redacted>`；实测 `sig=aa` 不出现（host 按设计可见，不是秘密）。 |
| A15 | 「远端命令 handler 可以 async 返回状态」 | **假**。`MPRemoteCommandHandlerBlock` 必须同步返回 → 用 `DispatchSemaphore` 桥接 actor 调用（系统在自己的队列回调，非主线程，无自死锁）；决策本体留在 `NowPlayingCommandRouter`，单测不打这条桥。 |

## 四、冲突处理

- **C1 `AVAudioSession` 与 CovaCore 平台中立口径冲突**：播放器层合法使用 AVFoundation/MediaPlayer，
  因此门禁的平台中立性扫描（字面 `#if`、iOS-only 令牌）**继续只覆盖 `Packages/CovaCore`**；
  播放器层的对偶不变量是「无 UI 框架 import」（3/10），覆盖率口径改用 iOS destination 的 xccov（9/10）。
  未新增任何 `#if`。
- **C2 `MPRemoteCommandCenter` 不需要 UIKit，但封面位图需要**：`MPMediaItemArtwork(image:)` 的入参是
  `UIImage` → 播放器层被门禁禁止引入 UI 框架。裁决：播放器只发布 `artworkURL`（脱敏载体）并留
  `NowPlayingArtworkAttaching` 注入点，位图挂载由 UI 层（G2 之后）实现；
  `MPNowPlayingController` 侧只做「异步调度 + 挂载成功标记」，不构造位图。
- **C3 `UIApplication.ScenePhase` 会拖入 UIKit**：前后台相位改为播放器自有
  `PlaybackLifecyclePhase(active/inactive/background)`，由 App 层转接（门禁 3/10 硬约束下的唯一干净解）。
- **C4 `HTTPTransport` 整包返回 `Data`**：不能用于音频大文件。新增 `PrivateAudioTransport`
  （`URLSession.bytes` + `FileHandle` 分块写盘 + `synchronize`），Bearer 由 `APICredentialProviding` 注入，
  出站 URL 必须先过 `CovaEnvironment.isProductionOrigin`。
- **C5 前一实例遗留的「双份测试块」**：`AudioSessionControllerTests.swift` 里同一 MARK 段出现两次，
  第一块引用已不存在的 API（`interruptionTypeRaw` / `AudioSessionNormalizer.interruptionTypeBegan`）
  且与第二块函数重名 → 整个包**从未编译成功**。处置：删除旧的、以「实现内部别名」为期望的那一块
  （它同时违反「测试不得与实现同错」的要求），保留并加强以 SDK 常量为输入的那一块。
- **C6 生命周期缺陷（A13）**：属于本轮新发现并修复的行为收紧（`AdvanceRejection` 新增 `.tornDown`），
  不改变任何既有裁决；既有 2 条 `CovaPlayer().assetOrigin` 断言继续通过。

### 5.1 队列与循环（`PlayQueue.step`，`trigger × mode × 位置`）

| 场景 | 裁决 | 依据 |
|---|---|---|
| `.off` 末项 `itemEnded` | `.stopped` → 进入 `.stopped` 终态，**不 wrap**；`engine.pause()` | design §5「不循环：队列尾播完即停」 |
| `.off` 末项显式 `next` | `.held`（索引不动、不进终态）→ 锁屏侧回 `noSuchContent` | 用户点击越界 ≠ 播完，不能伪装成终态 |
| `.one` 任意位置 `itemEnded` | `.repeated(at: 当前)` → seek 0 + play，**优先于**「后面还有曲目」 | 单曲循环语义（A2） |
| `.one` 末项显式 `next` | `.held` | 与 `.off` 同（`.one` 只改「播完」行为） |
| `.all` 末项（任何触发源） | `.moved(to: 0, wrapped: true)`；**单元素队列** → `.repeated` | 回绕即重来 |
| 首项显式 `previous` | `.all` → 回绕末项；`.off`/`.one` → `.held` | design §4 ⏮ |
| 首项 `itemEnded`（非末项） | 正常前进 `+1` | 只有末项才有回绕/终止问题 |
| `itemFailed`（任何模式） | **必须离开当前项**：末项回绕（`.one` 也回绕，不重复坏源） | A3；design §9「自动跳下一首」 |
| duration 未知时 `seekBySeconds(±15)` | 只钳下界 0，允许上界越界（`SeekClamp.durationUnknown`） | A4 |
| duration 未知 → 引擎后到 duration 且 `position > duration` | 位置纠正为 duration；若正在播 → 同一次 `receive` 内按「播完」继续（不派新任务，保持确定性） | A4/A5 |
| 目标越过 duration | 钳到 duration 且等同「播完」→ 按循环三态继续（`.one` 重播 / `.all` 回绕 / `.off` 末项停止） | design §3 拖到尾部 |
| 目标非有限（NaN/Inf） | `.rejected(.nonFiniteTarget)`，状态与引擎都不动 | 防 NaN 污染快照 |
| 队列清空（`removeAll` / 移除致空） | 无当前项 → 移除当前项致空时 `state = .stopped` + `stopAndRelease` + position/duration 归零 | 快照必须自洽 |
| 移除**当前**曲（队列仍非空） | 指向**同位置新项**（末项被删则退一位）；播放中 → 立即装载并继续播（保持播放意图），暂停中 → 只换元数据不启动 | 用户预期 |
| 移除**非当前**曲 | 当前索引按「之前移除则左移一位」修正，播放不中断 | 索引不变量 |
| 拖拽排序（移动当前项） | 当前索引 = 目标索引（身份跟随自身） | 队列面板高亮不跳 |
| 拖拽排序（移动他项跨过当前） | 净位移修正（先移除后插入），再钳制到合法区间 | 同上 |
| 空队列上 `next/previous/start` | `.rejected(.emptyQueue)`；有队列但未选曲时用户显式导航 = 选首项，自动推进无意义 → `.rejected(.noCurrentItem)` | 未选曲是合法中间态（append/insert 保持它） |
| 连续 3 次失败 | 第 3 次 → `isFailureTerminal = true` + `.stopped`，**停止自动推进**；取消类失败不计入；成功事件（`.playing`）清零连击 | design §9 |
| 终态的恢复条件 | 用户显式 `resume()` / `start()` → 清 `failureStreak` / `isFailureTerminal` 并重新装载当前项；此后自动推进恢复 | 「停止并提示」后必须由人接手 |
| generation 推进 / 换号 / 登出 | 丢未决上报 + `stopAndRelease` + 清队列 → `.stopped`；**登录（nil→owner）不算失效** | D8；TD-19 补发语义 |
| teardown 之后 | `start*`/`resume` 一律拒绝（`.tornDown` / 直接早退），`receive` 与 `seek` 拒绝 | A13/C6 |

### 5.2 中断与路由（`AudioSessionReducer`，全部输入以 SDK 常量为键）

| 输入（SDK 常量） | 决策 | 状态账 |
|---|---|---|
| `InterruptionType.began` | `.pause` | `isInterrupted = true`，`shouldResume = true` |
| `InterruptionType.ended` + `InterruptionOptions.shouldResume`（或已记录意图） | `.resume`（来电后自动续播） | 清 `isInterrupted`/`shouldResume` |
| `InterruptionType.ended` 且**无**意图（用户主动暂停后才被中断） | `.none`（不得自动出声） | 清 `isInterrupted` |
| `RouteChangeReason.oldDeviceUnavailable`（拔耳机/拔线/蓝牙断连） | `.pause`，**无条件**（探针此刻仍可能报有输出） | 清 `shouldResume` → 插回不自动续播 |
| 其它原因但探针报「已无输出」 | `.pause`（兜底） | 清 `shouldResume` |
| `newDeviceAvailable` / `categoryChange` / `other` 且有输出 | `.none` | **不**清 `shouldResume` |
| 未识别通知名 / 类型缺失或越界 | `.unrecognized` → `.none` | 保持可观测，不猜测 |
| `stop()` / `teardown()` | 不产生命令 | 状态归零 + 反激活会话 |
| 观测者生命周期 | `start()` 注册 `interruptionNotification` + `routeChangeNotification`；`stopObserving()` 必须清空 token 与 weak gate | 通知残留是本仓红线 |

### 10.4 存疑点（交协调者裁决）

1. **无 `Content-Length` 时判不出「早断」**（NEEDS 候选 `PRIVATE-AUDIO-CONTENT-LENGTH`）：
   `PrivateAudioReceipt.isComplete` 在 `expectedBytes == nil` 时只要字节数 > 0 就为真 —— 服务端不声明长度时，
   「连接中途断但已收到前半段」与「完整小文件」在客户端不可区分。希望契约要求音频响应**必须**声明
   `Content-Length`（或给 checksum），否则 D7 的「校验非空」只是「校验不为零字节」。
2. **C2 的 `http.url == nil` 端到端无法离线构造**：实测 URLSession 会替换 `URLProtocol` 交付的响应对象
   （自定义子类的 `url` override 被丢弃），且 `URLProtocol` 桩不触发重定向跟随（只捕获到 1 跳、302 原样上浮）。
   已用纯决策面 `AudioAuthorityMatch.matches(requestURL:responseURL: nil) == false` 钉住判据；
   真实跳转链的复现要本地 HTTP 服务器，与「唯一出口 = `https://covalink.cn`」硬边界冲突 → 建议进 G4 真机冒烟清单。
3. **m13b 是等价变异**（见 10.2）：说明 `removeVerified` 的「删除后复核」才是真正的判据，
   `do/catch` 只是同一判据的第二道；不算测试漏洞，但意味着 `catch { return 0 }` 分支无法被独立杀掉。
4. **M7 的去重让下载跑在无结构 `Task` 上**：调用方被取消不再自动取消下载（旧代码里靠传输自身的
   `Task.isCancelled`）。当前协调器用 `loadGeneration` 守卫忽略过期结果，不依赖取消传播；
   若 M1 之后要「滑动切歌即掐断下载」，需要加 `withTaskCancellationHandler` + 等待者计数（最后一个等待者离开才取消）。
5. **`discardPrivateAudio` 有默认空实现**：真实实现（`PrivateAudioFetcher`）已由协议面测试钉住；
   但「第二个会落盘的准备器」出现时，默认空实现又是一个静默漏清点。要不要现在就去掉默认实现、
   强制所有准备器表态？（去掉会牵动 `StubSourcePreparer` / `GatedSourcePreparer`，本组按指令只做新增。）
6. **`purgeStale` 按代次扫全部 owner 目录**：同账号代次推进用它（不误删当代缓存），
   跨账号/登出用 `purge(owner:)`。若将来允许「多账号同时在线」，`purgeStale` 需要按 owner 限定。
7. **m12 只收紧文件（0600），目录仍是默认 0755**：owner 目录名是 principal 的 hex（不可枚举内容，
   但目录本身可被列出）。是否把 owner 目录收到 0700、或加 `NSFileProtectionComplete`（`protectionKey`）
   需产品/安全裁决 —— 后者会改变「设备锁定时不可读」的播放行为。
8. **`PLAYER_MIN` 只报数未改基线**：本组实测真实通过数 **322**。与并行实例（PlaybackCoordinator/PlayQueue）
   合并后需按合并后的实测值再抬，本组没有动 `Scripts/test-count-baseline.env`。

### 11.1 收敛成的那条不变量（R9 续体守卫）

F-1 / F-2 / F-5 / F-7 / F-8 的病根是同一条：**跨挂起点回来的续体没有被统一归因**。
上一轮把三件事各写了一份、各漏一处（M10 只封事件路径 → 装载续体仍开放；P2 只封代际 →
迟到失败 / 在途 seek / load 失败仍开放）。本轮把它们收成一个命名守卫
`PlaybackCoordinator.continuationIsCurrent(generation:claimingEngineItem:kind:requiresPlaybackIntent:)`，
所有续体点只允许调用它：

| 条件 | 判据 | 载体 |
|---|---|---|
| (a) 装载代际 | `generation` 仍是当代且未释放；传 `nil` = 本续体不源自装载 | `loadGeneration` + `inFlightLoad` 台账 |
| (b) 引擎归属 | 引擎里**确实**装着被宣称的那一项，且本代际没收到过 load 失败 | `engineEpisodeItemID` + `engineOwns(_:kind:)` |
| (c) 用户意图 | 未被显式暂停、未进入失败终态、未释放 | `userWantsPlayback`（新增账本）+ `isFailureTerminal` + `tornDown` |

新增的第三本账是 **`inFlightLoad`（在途装载台账）**：`(generation, handedToEngine, failure)`。
它把「引擎有没有被交给当代条目」变成可判定的事实 —— `prepareSource` 挂起期间引擎里装的还是
上一件，那一刻到达的任何上报都属于已被取代的条目（F-2 的归因分界）。

台账的**结束**用 `defer { finishLoad(generation) }` 钉死：`loadCurrent` 有 7 个提前返回，
漏掉任何一个都会让「装载在途」永久成立，反过来把所有 seek / 事件归约误杀。

守卫接入点（本轮全部改为调用同一函数，无就地重写条件）：
`loadCurrent` 的 5 个回写点、`seek(toTarget:)`、`receive` 的 `.playing/.paused/.buffering/.position/.duration`、
`handleItemEnded`、`receive(.failed)` 的归因、`apply(.repeated)` 的进入闸门与返回前复核（共 3 处）。

### 11.3 F-6 的「非缺陷」论证（不隐瞒分歧）

探针要的是「成功装载即归零 `failureStreak`」。这条**不成立**，且修它会破坏锁定裁决：

1. design §9 的「连续 3 次失败」数的是**连续失败的曲目**，而 `engine.load` 成功 ≠ 播放成功。
   `testThreeConsecutiveFailuresEnterTerminalState` 的现实形态正是「三项装载全部成功、
   播放全部失败」—— 装载成功就归零的话，连击永远到不了上限，§5.1 表里那一行直接失效。
2. 归零点已经存在并且是对的位置：引擎上报 `.playing`（真正播起来）→ 连击归零，
   既有 `testSuccessResetsFailureStreak` 钉着；探针自己也承认「生产 `AVPlayerEngine.play()`
   会 yield `.playing` 归零」。
3. 所以缺陷只是**决策层的终态标记**没跟上：恢复装载已经成功，`isFailureTerminal` 还挂着 true
   （要等引擎事件才解除）。本轮把标记接上，并用新测试**同时钉住**「装载成功不清连击」
   这条反向期望，避免下一轮把它当漏改再翻出来。

### 11.7 本组留下的存疑点

1. **`observation` 与 `claim` 两档严格度**是本轮新引入的口径：观测类事件（`position`/`duration`）
   在 `engine.load` 在途时**被采信**（那一刻引擎里装的就是当代条目），宣称类一律不采信。
   分界依据是「引擎的装载代际只在 `engine.load` 真正发生时推进」这一既成事实
   （`EngineEventGate`）。若评审认为观测类也该一律等到落地，只需把 `engineOwns` 的放宽分支删掉，
   但 `testLateEnded…` 那类「屏障事件必须在落地前被消费」的写法要一并重做。
2. **`continuationIsCurrent` 对 `claimed == nil` 是跳过 (b)**：调用方若在当前项为空时传 `nil`，
   守卫不会拦。现网调用点都在传 `queue.current?.id` 且前置了 `queue.current != nil`，
   下一轮如新增调用点请显式 `guard let`，不要让 `nil` 溜进守卫。
3. **`handleItemEnded` 仍不能区分「上一项的迟到 ended」与「同项的重复 ended」**（裸 `.ended`
   不带归因，§存疑点 1 老问题）：本轮只补了「装载在途 / 引擎未持有当前项 → 不推进」这半边，
   真正那半边仍在引擎侧闸门。若契约给 `.ended` 带上条目 id，两侧可以合并成一处判定。
4. **`.buffering` 的采信面收紧了**：原先 `state == .loading` 时也允许引擎把状态打成
   `.buffering`；现在要求「正在播 + 引擎持有当前项 + 无装载在途」（装载在途时的缓冲上报属于
   上一件，且 `.loading` 已经如实表达了「还没到手」）。全量测试无一处依赖旧口径。
5. **`state = .stopped` / `.paused` 这类「少报」写入没有接守卫**：守卫只拦「多报」
   （声称在播、声称落点、声称推进）。少报不误导 UI，且收敛方向安全，故按现状；
   若评审要求「一切状态写入都要归因」，需要另立一条更严的规则并逐点评估。

`caller.cancel()` 之后 `committed=1`、盘上多一份文件。既有 `GatedPrivateAudioTransport` 的
挂起点同样不理会取消，所以「到底有没有终止」在旧夹具上**读不出来**。

**修法**（`PrivateAudioFetcher.swift`）：
1. 新增 `awaitTransfer(_:)`：`withTaskCancellationHandler { await task.value } onCancel: { task.cancel() }`，
   并在返回后 `guard Task.isCancelled == false` —— 完成与取消撞同一瞬间时也不投递可播地址。
   合流路径（`inflightTransfers[key]`）与自持路径（`startTransfer`）走**同一个**等待口，
   于是「取消是共享的」这条语义只有一份定义。
2. `localizedURL` 入口 + `performTransfer` 入口 + **提交前两处**复核取消（后者是对「不合作出口」
   —— 字节已在缓冲、取消要到下一块才被看到 —— 的唯一防线）。

**永久测试**（`PrivateAudioFetcherTests`）：
`testUpperLayerCancellationTerminatesInFlightTransfer`（复审探针同名：终止 + 不投递 + 登记表摘除 +
`.inflight` 无残留）、`testCancellationByBothMergedCallersDeliversNoPlayableURL`（合流腿；刻意两个调用者
一起取消，使「加入者是否已走到合流分支」不影响结论 → 不依赖调度顺序）、
`testUncooperativeTransportStillCannotDeliverAfterCancellation`（不合作出口形态：传输**确实跑完**
`completedCount==1`，仍不得提交、仍不得被下一次请求当可用缓存复用）。

#### MAJ-3（Major）：`cancelInFlightTransfers()` 的默认空实现让「清理前作废」不成义务

**复现**（评审探针同形态）：作废动作被静默跳过时，`purgeAll()` 之后那一路照样跑完并投递
`writeFailed(状态码 4)`；盘上干净只是 `commitMove` 撞 ENOENT 的巧合。

**修法**：删除 `public extension PrivateAudioTransport { func cancelInFlightTransfers() async {} }`
—— 现在是**必须实现**的成员（漏实现直接编译不过），并把它从「可选钩子」改写成协议里的义务说明。
所有 conformer 补齐：`URLSessionPrivateAudioTransport`（原有）、测试侧
`StubPrivateAudioTransport`（新增显式实现 + 记账）、`GatedPrivateAudioTransport`（原有）、
新桩 `CancellablePrivateAudioTransport`。

**永久测试**：`testPurgeIsNotDefeatedByInFlightTransferOnRequiredCancellation`（清理 → 作废被调用 →
在途终止 → 不投递 → 出口换代后仍服务下一次取回）、
`testInFlightCancellationIsARequiredWitnessNotADefaultNoOp`（经 `any PrivateAudioTransport` 协议面调用，
证明「义务在类型里」而不是「够得到具体类型才有」）。既有

#### MAJ-4（Major）：被作废的传输计入失败连击

**机理确认**：`for try await byte` 与 `handle.synchronize()` 当时都不在任何 `catch` 内
（只有 `bytes(for:)` 段做了归一），所以裸 `NSURLErrorDomain/-999` 一路逃到准备器 →
`writeFailed(-999)` → `missingFile` → `countsTowardFailureStreak == true`。

**修法**：`URLSessionPrivateAudioTransport.writeAudio` 把整段读循环 + `synchronize()` 包进
`do/catch`，交 `normalizedStreamError(_:)`：已分类的 `PlayerError` 原样上抛（m14 短写口径不动）→
取消形态 → `.cancelled` → 其余 `NSURLErrorDomain` → `.badStatus(0)` → 其余 → `writeFailed(码)`；
收尾前再加一次 `Task.isCancelled` 检查。准备器侧 `PrivateAudioFetcher.isCancellationShaped(_:)`
是第二道（覆盖 `CancellationError` / `PlayerError.cancelled` / `URLError(.cancelled)` / 裸 -999）。

**永久测试**：`testRealTransportCancellationTerminatesInFlightStream`（真实出口 + 真实读循环：
`URLProtocol` 新增 `midStreamFailure` / `chunksBeforeFailure` 两个脚本位，先交响应头与一块字节再抛
-999，这才对应「会话在途被 `invalidateAndCancel()`」）、
`testMidStreamNetworkFailureIsNotSilentlyTreatedAsCancellation`（TD-9 反向对照：非取消的流内错误照旧
是失败且照旧计连击）、`testStreamErrorNormalizationTable`（归一判据穷举）、
`testInvalidatedTransferNeverCountsTowardFailureStreak`（账目腿：`.cancelled` → 不进连击，
外加 `NSCocoaErrorDomain/516` 不得被当成取消）。

### 13.3 组 2（MAJ-2 / MAJ-8 / min-2 / min-3 / min-5）：清盘与出口守卫

#### MAJ-2（Major）：`discardPrivateAudio(owner:)` 的默认空实现让清盘可被绕过

**复现**：协议带默认空实现时，「第二个会往磁盘写私有音频的准备器」只要忘记覆盖，就能让登出
静默变成空操作 —— 门面调用了、协议满足了、盘上一个字节都没动。

**修法**：删除 `public extension PlaybackSourcePreparing { func discardPrivateAudio(owner:) async {} }`。
义务从**运行时**上移到**编译期**：仓内 conformer（`PrivateAudioFetcher` / 三个测试桩）全部补齐，
「没有磁盘副作用」的实现现在必须显式写一行空操作（`StubSourcePreparer` / `GatedSourcePreparer`
都写了，那一行就是它们的免责申明）。包外（`Cova/**`、`CovaTests/**`）grep 确认无 conformer。

**永久测试**：`testSecondFileWritingPreparerIsDiscardedThroughProtocolSurfaceOnLogout`
（新原语 `FileWritingPrivateAudioPreparer`：**真的写文件**、不是 `PrivateAudioFetching`、
只经协议面清理 —— 门面无从「顺手去够实现方的 purge」）。
**编译面的证据**（无法写成 XCTest 断言，故留操作记录）：把
`struct NoOverride: PlaybackSourcePreparing { func prepareSource(...) }` 放进测试 target 后
`build-for-testing` 直接失败 —— 见 §13.4 表尾的一次性实测输出。

#### MAJ-8（Major）：`.publicDirect` 的 https 在引擎侧零出口判定 + `assetOrigin` 是死字段

**机理确认**：出口守卫只存在于私有音频准备器那一路（Bearer）；`.publicDirect` **从不经过它**，
而 `AVPlayer` 自己发请求 —— 于是 `https://cdn-other.invalid/a.m4a` 在引擎里拿到 `.success`，
`assetOrigin` 全仓只出现在门面构造与两处断言里。

**修法**：
1. `AVPlayerEngine.playableURL(for:egressOrigin:)` 把 `.publicDirect` 与 `.localized` 拆开，
   前者必须过 `isAllowedEgress(_:_:)`：**①** `CovaEnvironment.isProductionOrigin`（与准备器
   同一判据、同一实现）**②** 权威与门面声明的那台出口同源（`AudioAuthorityMatch.origin(of:)`，
   规范端口折叠）。注入非法出口只会「一律拒绝」，不可能因此放宽。
2. `AVPlayerEngine(egressOrigin:)` 成为指定初始化器；`CovaPlayer.init` 的 `engine` 参数改为
   `(any PlayerEngine)? = nil`，默认装配变成 `engine ?? AVPlayerEngine(egressOrigin: assetOrigin)`
   —— `assetOrigin` 从此**被消费**（`CovaTests` 对它的两条断言一字未动，仍然成立）。
3. 门面注释里的空承诺改写为实际消费点。

**永久测试**：`testPlayableURLRefusesBearerItemsAndAcceptsDirectAndLocalized`（加固：新增
异主机 / 显式非规范端口 / 注入非法出口三条拒绝腿 + `:443` 正向对照腿）、
`testEngineEgressJudgementTable`（判定表穷举）、
`testAssetOriginIsConsumedByTheDefaultEngine`（默认引擎的基准 == `assetOrigin`；注入别的 origin
时跟着走；显式注入引擎时不被换掉）。
**夹具口径变化（如实标注）**：「接受公开直链」那一腿的夹具主机从 `cdn.covalink.example` 换成
生产出口 —— 这是被修复的判据本身要求的，不是弱化：断言数从 5 条增到 12 条，
且 `.example` 主机从此**必须**被拒绝（已作为拒绝腿钉住）。全程零网络（只断言纯映射，
没有任何 `AVPlayerItem` 真的装载这条地址）。

#### min-2（Minor）：同源判定与出口守卫对 `:443` 口径不一致

`isProductionOrigin` 放行 `https://covalink.cn:443`，而 `AudioAuthorityMatch.origin(of:)` 把
`covalink.cn` 与 `…:443` 判成两台主机 → 合法的带端口重定向被误杀（NEEDS-15 未解锁前又多一处堵点）。
**修法**：只有**非规范**端口才写进 origin（`CovaEnvironment.apiPort` 为唯一事实源，不写字面 443）。
**永久测试**：`testCanonicalPortMatchesProductionAuthority`（探针同名，含 TD-9 反向对照：
`:8443` / 子域 / 降级 http 仍算换权威）、`testLandingOnCanonicalPortStillDeliversBytes`
（真实管道那一腿：带 `:443` 的落地照常交付字节）、`testAuthorityMatchDecisionTable`（加固）。

#### min-3（Minor）：同键合流在 `expectedBytes` 不一致时换件

**机理**：加入者复核自己的期望长度不过 → 落到「另起一路往同一个目标路径覆盖提交」，
于是先交付方拿到的 24 字节被后加入方的 48 字节换掉（盘上实得 48），与既有
`testConcurrentSameKeyRequestsTriggerExactlyOneTransfer` 自陈的「两个调用者必须拿到同一份内容」
直接冲突。**修法**：新增 `mergedOutcome` —— 一个 key 的字节数只由那一次传输决定；
期望与实得不一致 = 元数据打架 → 如实回 `.truncated(expected:actual:)`，**一个字节都不删、不覆盖**；
只有「文件确实不见了」才退回自己重取。
**永久测试**：`testMergedSameKeyRequestsCommitOneConsistentPayload`（探针同名）。会合点用新原语
`SignallingCredentialProvider`：凭证读取是加入者进入合流分支前**唯一**的挂起点，它一返回就把
加入者的续体排进取回器信箱（FIFO），测试随后的一次 actor 回合必然排在它之后 —— 不靠让步、
不猜时间（D16⑤）。

#### min-5（Minor）：`purgeStale(before:)` 跨 owner 全目录扫描

**修法**：作用域收窄到**当前凭证快照的那个 owner** 目录（代次是账号内部的事实）；
凭证不可知（未登录 / 读取抛错）时**一个都不删** —— 宁可留孤儿文件给下一次 `purge`，
也不替不明的身份做删除决定。协议注释同步改写为这条口径。
**永久测试**：`testPurgeStaleNeverReachesAnotherOwnersFiles`（含 fail-closed 腿：signedOut 凭证 → 0 删除，
且 Bob 的文件仍在）。既有 `testPurgeStaleKeepsCurrentGenerationAndUnknownNames` 一字未动仍绿。
