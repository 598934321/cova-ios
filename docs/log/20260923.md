## §4 第 16 批：R11-1 / R11-2 —— 第 11 轮把我第 15 批的修法打穿了

**先说结论的形状**：第 15 批那把「入口摁声」本身是一次 `await`，而它把台账与用户意图的写入
留在了这次挂起**之后**；同时重播腿仍是「先 `seek`+`play`、后复核」。于是两个新洞：

- **R11-1**：被取代的重播腿挂在 `engine.seek` 上 → 用户换曲 → `loadCurrent` 入口摁声（唯一一次）
  → seek 返回 → 那句陈旧的 `engine.play()` 落在摁声**之后** ⇒ 旧项重新出声，读数已是
  `.loading(b)`，窗口 = b 的下载时长。评审的探针
  `testR11P1_supersededReplayPlayArrivesAfterTheEntryPause` 在 `e49b2ab` 上**实测红**。
- **R11-2**：入口摁声那段挂起里用户按 ⏯ ⇒ 续体随后 `userWantsPlayback = autoplay`
  把暂停**改写回播放** ⇒ 多一次播放上报（评审量到 `2 != 1`）、锁屏收到 `isPlaying=true`、
  状态声称 `.playing`。这是 F-1 早已承诺过的形状，被我自己新加的挂起点重新打开。

**修法（两处，都不引入新挂起）**
1. **引擎命令权** `engineCommandGeneration`：由 `loadCurrent` 在入口**同步**认领（在任何 await 之前），
   `invalidateInFlightLoad()` 里作废为 `nil`。重播腿在 `engine.seek` 返回后、出声之前先看这道闸；
   归属已换 ⇒ 不出声。出声之后若发现归属已换**且引擎至今仍装着我那一件**，才补一次 `pause()`
   ——「引擎还装着我的项」恰好保证这一摁不可能伤到用户的新曲（那才是 R9-1 的伤害面）。
2. **台账与意图一起落在摁声之前**：`engineEpisodeItemID = nil / userWantsPlayback = autoplay /
   state = .loading / position / duration` 全部前移到 `await engine.pause()` 之前，
   `defer { finishLoad }` 仍在最前。这样挂起窗口里用户的暂停只会**下调**意图，不会被续体改写。
   代价据实写清楚：这段窗口里读数已是 `.loading` 而旧声可能还在响一次 actor hop
   （不是分钟级窗口）—— 与「绝不越过用户的暂停」相比，这一寸是可接受的取舍。

**证据**
- 永久用例两条（`testSupersededReplayLegMustNotPlayAfterTheEntryPause` /
  `testUserPauseInsideTheEntryPauseWindowIsNotOverturned`），评审的挂起式引擎桩
  `R11OrderingEngine` 收为仓内永久件 `OrderingGatedEngine`。
- 本机 `xcodebuild -scheme CovaPlayer test` = **Executed 402 tests, 0 failures**。
- 变异自证：同时撤掉两道闸 ⇒ `-only-testing:PlaybackCoordinatorTests` =
  **115 tests, 5 failures**，失败的两条正是上面这两条；还原后源文件 `md5` 逐字节一致。
- `PLAYER_MIN` 400 → 402；版本 0.2.56(67) → 0.2.57(68)；整轮 `check.sh` 见 §5。
